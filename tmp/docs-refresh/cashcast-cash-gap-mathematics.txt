PR #60 не меняет bootstrap, квантили или формулу дефицита. Он разделяет медианный минус,
доступность вероятности и качество пульса; учитывает opening в интерфейсе и поясняет
последствия исторического среза.
1. Срез и подготовка истории
Пусть t=0 - дата as_of, B0 - начальный остаток, H - горизонт в днях, N=200 - число траекторий. Во
входе остаются только операции/остатки с датой <= as_of и планы, известные на срезе:
available_at <= as_of. В календаре учитываются будущие потоки внутри горизонта; план,
созданный сегодня, не считается известным в прошлом.
Окно - до 84 календарных дней. Если баланс между двумя наблюдениями не сходится с суммой
операций, пригодная статистическая история начинается после последней несверки. Пропуски
условно нулевые, полнота выгрузки не доказана.
Пусть h - календарная длина пригодного окна, fresh - наличие подтверждённого остатка не старше
трёх дней, согласованного с последующими фактами и B0.
simulation_eligible = (h ≥ 28) AND fresh
probability_eligible = (h ≥ 56) AND fresh
В 2.1 итоговая доступность вероятности дополнительно требует raw.risk.available от базового
симулятора. Если simulation_eligible=false, используется точечный fallback с p10=p50=p90. Эти
пороги относятся к пригодным календарным дням, не к количеству операций.
2. Регулярности и календарь без двойного счёта
Из истории выделяются регулярные платежи. Правило требует минимум три даты; типовая сумма
- медиана дневных сумм, отклонение сумм до 35%. Проверяются недельные, двухнедельные,
месячные и квартальные интервалы. Регулярные операции исключаются из нерегулярной
истории и отдельно проецируются в календарь.
Ручной план использует remaining_amount_minor. При однозначном совпадении с регулярностью
он заменяет соответствующее ожидаемое событие. Обозначим итоговые календарные
поступления и списания через Kin(t) и Kout(t).
3. Сезонная оценка потоков
I(d) и O(d) - нерегулярные поступления и расходы исторического дня; w - день недели, n(w) - число
дней этого типа в пригодном окне. Средние считаются отдельно:

4. Парный недельный bootstrap
Для каждого будущего семидневного блока случайно выбирается исторический семидневный
блок с тем же днём недели начала. I и O берутся парой из одних дней. Так сохраняется часть
зависимости между поступлениями, расходами и соседними днями. Процедура повторяется
N=200 раз; фиксированный seed делает выборку воспроизводимой.
Для траектории s денежный баланс равен:
Bt(s) = Bt−1(s) + It(s) − Ot(s) + Kin,t − Kout,t
B0(s) = B0
Инкрементальный расчёт переиспользует совместимую выборку/траектории и обновляет
денежные дельты. При одинаковом входе и seed результат должен совпадать с полным.
Контрольные точки разных model_version не смешиваются.
5. Квантили и точечный fallback
Для каждого t квантили берутся по 200 значениям B_s(t):
p10t = Q0.1({Bt(s)})
p50t = Q0.5({Bt(s)})
p90t = Q0.9({Bt(s)})
В коде используется линейная интерполяция соседних порядковых статистик с позицией q*(N-1),
затем округление до копеек. p10/p90 - эмпирический разброс симуляций, не подтверждённый
доверительный интервал реального будущего.
При недостаточном качестве симуляции остаток рассчитывается накоплением ожидаемого
чистого потока; диапазон схлопывается. Ни наличие p50, ни отсутствие минуса на нём не
подтверждают пригодность вероятностной оценки.
В общем случае медиана суммы не равна сумме медиан: изменение p50 не обязано совпадать с
ожидаемым приходом минус расход. Поэтому точное разложение сохранённого минимума

6. Разрыв, первый минус и резерв
Положим M(0)=B0 и M(t)=p50(t) для t=1..H. Отрицательные подряд идущие точки образуют эпизод;
ноль закрывает его. Точка t=0 участвует в расчёте.
D = max(0, −min0 ≤ t ≤ H Mt)
first_negative: первая дата с Mt < 0, t = 0…H
UI medianGap показывает first_negative и D независимо от risk.available. Если M(0)<0, это
существующий дефицит на as_of. Карточка first_new_gap_date отдельно ищет начало первого
нового эпизода позже среза, в том числе после восстановления существующего минуса.
Резерв required_reserve_minor=D - постоянная добавка к начальному остатку, делающая весь
медианный ряд неотрицательным. Это не кредит с возвратом и не резерв, гарантированно
покрывающий все симуляции. Длительность считается по отрицательным дням, включая срез;
день восстановления не включён.

7. Вероятность минуса
Обозначим 1[условие] как индикатор: 1 при выполнении, иначе 0. В версии 2.1:
Pday,t = (1 / 200) ∑s=1…200 1[Bt(s) < 0]
Pperiod = (1 / 200) ∑s=1…200 1[min1 ≤ t ≤ H Bt(s) < 0]
Например, 60 траекторий с минусом из 200 дают 30%. Общая вероятность не вычисляется
суммой или максимумом дневных; один сценарий может быть отрицательным много дней. Шаг
доли при 200 траекториях - 0,5 процентного пункта, без гарантии точности.
День t=0 исключён из P_period. Если B0 уже отрицательный, это вероятность будущего
отрицательного остатка, не возникновения нового разрыва. Медиана может быть положительной
при ненулевом P_period: часть траекторий уходит в минус, хотя дневная медиана остаётся

8. Preview действий
Для финансирования L с полной стоимостью C, получением в день a и возвратом в r:
M′t = Mt + L · 1[t ≥ a] − (L + C) · 1[t ≥ r]
Сумма со стоимостью возвращается полностью; за горизонтом долг показывается отдельно.
Финансирование завтра не покрывает уже существовавший сегодня минус.
Для переноса разрешённого расхода A с дня a на более поздний b:
M′t = Mt + A · 1[a ≤ t < b]
Для задержки поступления знак поправки обратный. Эпизоды и D пересчитываются; улучшение
равно D_base-D_preview и может быть отрицательным. Быстрый preview меняет только медиану и
возвращает probability=null. Для новой вероятности нужен полноценный сценарный run. Реальные
платежи не меняются.
9. Качество пульса и регрессия PR #60
Пульс использует simulation_eligible, а не probability_eligible или risk.available. Без денежных
данных/потоков - unknown. При близком минусе - risk; при сигналах подушки/стресса или более
дальнем минусе - watch. Если сигналов нет, недостаточное качество даёт unknown; иначе ok по
медиане. Cash unknown не превращается в общий ok.
Синтетическое демо на as_of=01.08.2026 содержит шесть дней с 27.07. B0=260 400 ₽, минимум
p50=247 900 ₽, конец 30-дневного горизонта=289 500 ₽. D=0, вероятность недоступна, пульс
unknown. Перенос среза назад уменьшил историю, но не создал минус.
Добавление известного на срезе расхода 400 000 ₽ на 03.08 создаёт видимый разрыв с этой даты
и максимум дефицита 152 100 ₽ при probability=null. План с available_at=24.10 не влияет на
августовский расчёт. Это синтетическая проверка поведения, не измерение реальной точности.
