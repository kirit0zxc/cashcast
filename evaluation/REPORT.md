# B4: воспроизводимая оценка аналитики CashCast

## Данные и разбиение

Источник — синтетический датасет организаторов, не smoke-набор: 150 компаний,
222420 операций, 2024-10-01–2026-09-30. ZIP SHA256:
`e753802b7f7a2eecb7b5a558f9923b529e711c40fe431774750904b62ec79987`.
Использован только all_operations.csv, ИНН прочитан строкой; справочник с будущими
last_operation_date/operations_count не используется как признак.

Горизонт30 календарных дней, seed42,200 bootstrap-путей. Validation срезы:
30апреля,31мая,30июня,31июля2026. Все validation-строки, включая проверку полноты
целевых значений, ограничены31августа. На517 принятых company-cutoff folds сравнивались
те же baseline и окна28/56/84. По минимальному MAE дневного остатка выбрано84;
публичная модель `seasonal-block-bootstrap-1.0-w84`, фабрика использует это окно.
Сентябрьский срез31августа, цель1–30сентября, запускается только после записи config.

Первоначальная проверка quality gate последнего validation-среза могла использовать
остаток1сентября (8folds). Reviewer обнаружил это; граница исправлена, прежние три
кандидата пересчитаны. Сентябрьские результаты до исправления уже были просмотрены:
последующая оценка — технически исправленный повтор, не новый нетронутый holdout.
После просмотра holdout математическая модель, сетка окон и критерий выбора не менялись.
Аддитивное model_version property не меняет численные результаты.

## Риск: ограничения существенны

Вероятность доступна у117 из122folds (3510дней); остальные не оцениваются как нулевая
вероятность. Оценка проверяет отрицательный наблюдаемый остаток одного счёта вместе
с пополнениями владельца, не скрытый дефицит до поддержки и не все деньги компании.

- Покрытие интервалаp10–p90:77.44% при номинальных80%.
- Brier дневного отрицательного остатка:0.047736.
- Brier хотя бы одного минуса за горизонт:0.107358.
- Постоянная вероятность, взятая из validation (23/494=0.046559), даёт на тех же117folds
  Brier0.056426. Всегда нулевая вероятность даёт0.059829. **Модельный риск хуже этих
  простых ориентиров по Brier; калибровка не подтверждена.**
- При пороге0.5:7 истинных предупреждений,19 ложных,0 пропущенных из7 наблюдаемых
  положительных случаев; precision26.92%, recall100%. Всего7 положительных случаев:
  такой recall не доказывает надёжность на других данных.

Модельные вероятности допустимы только с явными допущениями. Их нельзя представлять
как проверенную вероятность банковского дефолта или гарантию кассового разрыва.
Дальнейшее улучшение требует отдельного validation для калибровки/порогов и нового
непросмотренного периода; сентябрь повторно использовать для подбора нельзя.

## Полнота целей и исключения

Validation:600 возможных company-cutoff folds,517 приняты; исключены21 без прошлого
остатка,38 со старым начальным остатком,14 с несверкой целевых остатков,10 без
подтверждения покрытия конца горизонта. Holdout:150 возможных,122 приняты;
8 stale opening,1 несверка,19 неподтверждённое конечное покрытие.
Отсутствие операций само по себе не доказывает закрытие компании или нулевой поток.
Для принятых folds дневной факт реконструируется по операциям и сверяется со всеми
наблюдаемыми остатками; нельзя исключить неизвестные взаимно компенсирующие пропуски.
Отбор по полноте целей раскрыт и может смещать оценку в пользу более полных выгрузок.

## Воспроизведение

Из корня репозитория после установки зафиксированных backend-зависимостей:

```sh
python evaluation/audit_dataset.py --zip /path/cashflow_dataset_participants.zip --output evaluation/dataset-audit.json
python evaluation/backtest.py --zip /path/cashflow_dataset_participants.zip --phase validation --config evaluation/selected-config.json --output evaluation/validation.json
python evaluation/backtest.py --zip /path/cashflow_dataset_participants.zip --phase holdout --config evaluation/selected-config.json --output evaluation/holdout.json
```

Использовать Python3.12 из backend/.venv либо установить PYTHONPATH через скрипт
(он сам добавляет backend). Validation должна запускаться раньше holdout. При изменении
причинных исходников/датасета holdout отвергает устаревший config; hashes нормализуют LF.
Snapshot/API не участвуют в чистом backtest и исключены из source fingerprints.
JSON содержит prediction_sha256, source_fingerprints, model metrics, per_cutoff,
cohorts и причины исключения. Сырые строки/назначения/покомпанейные прогнозы не публикуются.

Проверки из backend:

```sh
python -m pytest tests/analytics tests/test_baseline.py -q
ruff check . ../evaluation
# Полный pytest — только с CC_TEST_DATABASE_URL на выделенную PostgreSQL БД *_test.
```

Нет эталонных категорий, истинных дат обязательств и реальных плановых счетов:
accuracy категорий/matching и качество сценарных допущений этим датасетом не измеряются.
Эти сервисы проверены детерминированными тестами, сценарные счета не выдаются за
данные организаторов. Все B-пакеты передаются A точными SHA; состояние интеграции и CI
фиксируется отдельно в coordination/B.md. READY чистой аналитики не равно VERIFIED приложения.
