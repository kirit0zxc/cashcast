## Решение

Кандидат остаётся исследовательским: production_activated=false,
probability_calibrated=false, release.allowed=false. Продуктовая вероятность остаётся
null, работающая seasonal-guarded модель не меняется. Это шаг исследования, а не
готовый надёжный классификатор кассового разрыва. Розничные данные1990-х и отрицательный
EOD не доказывают качество на современных МСП и неоплаченных обязательствах.
1998 уже изучался: результаты ретроспективные, не новый нетронутый holdout.

## Воспроизведение

После установки evaluation/real-data-requirements.txt (те же Python3.12/CatBoost1.2.8):

```sh
python -m evaluation.risk_candidate.run --berka data/raw/berka/trans.asc --baseline-weights data/raw/berka/risk.cbm --weights data/raw/berka/risk-v2.cbm --output evaluation/risk-candidate-v2-results.json
```

Исходные данные и веса v1 должны совпасть с SHA из berka-risk-results.json.
Версии библиотек, SHA исходников/протокола (UTF8 с LF) и новых весов записаны в JSON.
Скрипт отклоняет изменение кода во время расчёта. Модель v1 не перезаписывается;
сырые строки/идентификаторы/веса не коммитятся. Повтор с теми же параметрами используется
для проверки окончательного кода и метаданных, без нового подбора по1998.
