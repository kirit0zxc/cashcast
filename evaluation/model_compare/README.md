# Сравнение моделей прогноза остатка: пакет для проверки

Текущий протокол — v2 (`evaluation/MODEL-COMPARE-PLAN-v2.md`), записан до запуска по итогам независимого
аудита v1. Протокол v1: `evaluation/MODEL-COMPARE-PLAN.md`. Отчёт: `evaluation/MODEL-COMPARE-REPORT.md`.
Обучение и оценка выполнялись в Google Colab. Ноутбук с теми же шагами — `out/colab_run.ipynb`.

## Запуск

Из корня репозитория (нужен `backend/app` для реестра продуктовых моделей), Python 3.12+:

```
pip install lightgbm scikit-learn numpy matplotlib
python -m evaluation.model_compare.run --zip data/cashflow_dataset_participants.zip --output out --export
```

Пример вызова сохранённых моделей на одном снимке (только данные до `--as-of`, факт не нужен):

```
python -m evaluation.model_compare.predict --zip data/cashflow_dataset_participants.zip \
    --models out/models/2026-08-31 --company C001 --as-of 2026-08-31
```

`--companies` и `--smoke` нужны только для быстрой проверки кода; их числа не являются результатом.

Бустеры LightGBM сохранены текстом (`lightgbm.Booster(model_file=...)`), логистическая регрессия — JSON
с медианами импутации, средними, масштабами, коэффициентами и свободным членом. Pickle не используется.
`run.py --export` загружает сохранённые веса обратно и пишет в `results.json` максимальное расхождение
с исходными прогнозами (`reload_max_abs_diff_*`).

## Схема обучения

- Окна истории — 84 дня до `as_of`, сетка `as_of` каждые 7 дней с 28.10.2024.
- Для среза `c` в обучение идёт окно, только если `as_of + 37 дней <= c`: 30 дней цели и 7 дней на
  подтверждающий наблюдаемый остаток закончились до среза. Незавершённые цели не используются.
- Модели обучаются заново на каждом из 5 срезов: 30.04, 31.05, 30.06, 31.07 (validation; данные, включая
  проверку целей, обрезаны по 31.08) и 31.08 (holdout, цель 1–30.09).
- Обучающие и контрольные окна исключаются теми же правилами, что в B4 (`evaluation/backtest.py::fold`):
  нет прошлого остатка, остаток старше 3 дней, нет подтверждения конца горизонта, факт не сверяется
  с наблюдаемым остатком. Счётчики причин и компании, у которых нет ни одного обучающего окна,
  лежат в `training_scheme.json`. Отдельного отбора компаний нет.
- Признаки используют только операции и остатки до `as_of` включительно. Регулярности находит продуктовый
  `CalendarRecurrenceDetector` по операциям до `as_of`.
- Маска качества (v2): дни окна до последней несверки остатка, известной на `as_of`, становятся NaN, как
  продукт обрезает историю после несверки. Обучающие окна при этом не удаляются.

## Кассовый разрыв, пороги и ансамбль

- Метка окна — хотя бы один отрицательный остаток на конец дня за 30 дней после `as_of`. Факт
  восстанавливается из остатка на `as_of` и дневных потоков и сверяется с наблюдаемыми остатками.
- Метрики риска считаются на всех окнах, где доступна вероятность текущей модели, и отдельно на новых
  разрывах при неотрицательном старте (`holdout_new_gap`, колонка `new_gap_eligible`). Обучение идёт
  на всех окнах; признак `opening_negative` знает знак старта.
- Порог 0.5 — порог продукта. Второй порог выбран на validation по максимуму F1 на сетке 0.05–0.95
  (при равенстве берётся больший) и без изменений применён к holdout.
- Отдельные модели нового разрыва учатся только на окнах с остатком ≥ 0, их порог выбирается
  на validation новых разрывов. Метрики риска даны на общей с продуктом выборке и на всех окнах.
- Ансамбли 0.5/0.5: 2.1 + LightGBM v2 (квантили усредняются — это не квантили смеси) и
  persistence + LightGBM v2 (только медиана и потоки). Веса заданы до запуска. Кандидат выбирается по MAE
  остатка на validation и должен обойти 2.1, B4 и persistence (правило в плане v2).
