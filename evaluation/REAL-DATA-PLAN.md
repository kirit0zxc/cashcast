# Реальные данные и кассовые разрывы: протокол до обучения

24.10.2026 владелец одобрил предложение: внешний тест MoneyVis, обучение кандидата
прогноза потоков и поиск примеров новых разрывов. База: 8168ec9. Сырые данные и
веса остаются вне Git. Никакой автоматической смены продуктовой модели по одному клиенту.

## MoneyVis

Один розничный счёт, исходные денежные единицы (CSV не содержит валюту).
Обратный порядок строк проверяется по датам и непрерывной сверке остатков.
EOD — последняя операция дня. Пропуски календаря: нулевые потоки и перенос остатка
при явном допущении полноты выписки. Не использовать категории/описания будущих операций.

Обучение CatBoost: даты целей до 31.12.2020, проверка настройки — 2021,
финальная проверка — доступная часть 2022. Никакой случайной разбивки строк.
Один фиксированный кандидат: два регрессора RMSE, depth=4, iterations=300,
learning_rate=0.04, seed=20261024, CPU threads=2. Отрицательные прогнозы потоков
ограничиваются нулём. Лаги 1/7/14/28, средние 7/28/84 и календарь.
Многошаговый прогноз рекурсивный, без подстановки настоящих будущих лагов.
Горизонты 7/14/30, срезы раз в 30 дней; окна разных горизонтов не независимы.
Ориентиры: последняя неделя и среднее по weekday за 84 дня.
Метрики: MAE потоков/остатка/конца горизонта, TP/FP/FN/TN, recall/precision;
при отсутствии класса recall/ROC-AUC не выдумываются. Единицы явно указаны.
Для отбора требуется >=5% выигрыша MAE остатка на validation на каждом горизонте.
Test не используется для донастройки. Даже выигрыш на одном клиенте не разрешает
активацию модели на МСП. Текущая продуктовая seasonal-guarded проверяется отдельно
на RUB fixtures и организаторских данных: иностранные суммы не импортируются как RUB.

## Berka

Первый шаг — аудит всех счетов: направление, диапазон, отрицательные остатки,
число счетов с ними. Дневной баланс нельзя выбирать по произвольному trans_id.
Положительный банковский остаток не доказывает отсутствие неоплаченных обязательств.
До подтверждённой хронологии/сверки Berka не становится обучающей разметкой.

До обучения Berka зафиксирован второй кандидат: CatBoostClassifier depth=4,
iterations=300, learning_rate=0.04, Logloss, seed=20261024, threads=2, без class weights.
Цель — новый отрицательный EOD в следующие 30 дней при opening>=0. Признаки:
только последние 84 дня, нормированные на средний расход; известный остаток,
потоки/их разброс, число отрицательных прошлых дней, календарь. ID счёта не признак.
Срезы раз в 30 дней от начала истории счёта. Окно признаков и цели целиком сверено.
Обучение: цели до конца 1996; validation: цели целиком в 1997;
test: цели целиком в 1998. SHA256(account_id)[0] mod5=0 — отдельные счета:
они не участвуют в fit/выборе порога, оцениваются отдельно в 1998.
Остальные счета — development, а не обязательно уже виденные в fit: некоторые
открыты позже. В отчёте отдельно указано реально пересекающееся с fit число счетов.
Фиксированная сетка порога [.01,.02,.05,.1,.2,.3,.5]; выбирается F2 на validation
при FPR<=10%, равенство разрешается в пользу большего порога. Метрики: confusion,
precision/recall, AP, ROC-AUC, Brier и константа частоты fit. Вероятность не считается
калиброванной; окна одного счёта зависимы. Автоматическая активация запрещена:
это проверка на старых розничных счетах, а не доказательство переноса на МСП.

## Продуктовая проверка

Карточка должна показывать новый дефицит при положительном opening, дату и сумму,
согласованное разложение и эффект финансирования/отсрочки без изменения фактов.
Дополнительно показываем срок до нового разрыва и минимальный невозвратный резерв
на начало горизонта по данной медианной кривой. Это не кредит, не вероятность
и не гарантия: возврат финансирования проверяется существующим preview отдельно.
DTO расширяется только добавочными полями; миграции не нужны.
