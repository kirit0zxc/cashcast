## Окружения и восстановление

Все команды ниже выполняются из корня этой ветки. Python3.12. Два отдельных окружения:

```powershell
py -3.12 -m venv .venv-research
py -3.12 -m venv .venv-chronos
& .venv-research/Scripts/python.exe -m pip install -r research_handoff/requirements-tabular.txt
& .venv-chronos/Scripts/python.exe -m pip install --index-url https://download.pytorch.org/whl/cpu torch==2.14.1
& .venv-chronos/Scripts/python.exe -m pip install -r research_handoff/requirements-chronos.txt
& .venv-research/Scripts/python.exe research_handoff/restore.py --downloads C:/path/to/downloaded-assets
& .venv-research/Scripts/python.exe research_handoff/run_tests.py
```

Версии — фактически использованные в авторском окружении; если пакет недоступен на другой ОС, зафиксируй замену и проверь воспроизводимость, не называй результат тем же автоматически. GPU не требуется: все наши измерения выполнены на CPU. Пакет18 имеет собственный README с вызовом полного CLI; дополнение21 также имеет README. `restore.py` оставляет их в игнорируемом `data/raw/handoff-packages/`.

Первый запуск незавершённого опыта24:

```powershell
$env:HF_HUB_OFFLINE='1'
& .venv-chronos/Scripts/python.exe -m evaluation.liquidity_risk.cumulative_flows evaluate
```

Это оценка сохранённых checkpoint100/300 и исходного Chronos; она сначала выбирает вариант на development январь–март и только затем считает другие периоды. Прогон может занять несколько минут. Не запускать `train` в уже использованной папке: обучение завершилось успешно, `training-completed.json` присутствует. Checkpoint200 намеренно не передаётся: он не входит ни в один заявленный критерий сравнения. `finetuned-ckpt` не дублируется, рабочие checkpoint100/300 переданы.

## Границы воспроизводимости

Исследования начаты на `a92bd5013b5b5d7e5008157815160b67fd762edf`. Ветка передачи обновлена fast-forward до `25918f9e859cb1ebb4ff226597ac36a77e39425c` (PR63, внешние источники). Аналитические модули/DTO/backtest на этой границе не изменились. Переносимый18 дополнительно содержит собственный проверенный код с хешами. Не смешивай его измерения с произвольно обновлённой продуктовой моделью.

Обучение большинства исследований — до конца2025; контрольные компании определяются `sha256(company)[0] % 5 == 0`. Эксперимент21 использует заранее заданное причинное обновление: обучающий `as_of +37дней <= дата модели`; контрольные компании исключены всегда. Поэтому21 проверяет обновляемую систему, а не только другую архитектуру.

Июль/август/сентябрь уже многократно просматривались. Это адаптивная ретроспектива, **не слепой контроль**. Новый случайный split этого не исправляет. На новых контрольных ответах запрещены подбор порогов, весов и переписывание критериев. Зафиксируй новую гипотезу в journal до кода и запуска.
