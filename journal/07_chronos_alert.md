# 07 — отдельное предупреждение по нижней границе Chronos

Одобрено автономно; до расчёта новых предупреждений.

Chronos дал лучшую validation MAE, но его медиана не ловит редкие разрывы. Это
ожидаемое различие точечного прогноза и риска. Проверяем предупреждение при пересечении
нуля нижним дневным квантилем, без выдумывания вероятности хотя бы одного минуса.

Фиксированная сетка q=.1/.2/.3/.4/.5, только нативные квантили Chronos-2. Предупреждение:
min(balance_quantile_q)<0, opening>=0. Остаток0не является отрицательным.
Выбор q по ранним6срезам январь—июнь: требовать recall=1 на наблюдённых5случаях,
FPR<=.25; среди прошедших минимальный FP, далее больший q. Если ни один не проходит,
новую политику не выбирать автоматически. Никакого расширения сетки по поздним ответам.

Сравнение с текущим horizon-bootstrap>=.5 на одинаковых доступных окнах. При короткой
истории Chronos использует прежнее предупреждение как явно обозначенный fallback.
Дневные квантили не складываются и не перемножаются в вероятность горизонта. Выход —
warning, quantile и дата/минимальный нижний остаток, score/probability отсутствуют.

Прогноз текущего p50и выпуск рабочего сайта не меняются. Ретроспективные периоды
уже просмотрены, поэтому не называем их слепым контролем. Результаты всех q на
ранних срезах сохраняются; поздний отчёт — только для замороженного решения.
Проверки: причинность предыдущего контекста, предупреждение монотонно по q, нулевая
граница, неизменность поведения fallback, предупреждение не маркируется вероятностью.
