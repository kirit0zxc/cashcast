# 01 — прямой прогноз потоков и проверка кассового разрыва

Статус: **одобрен пользователем: «Да, запускай по этому плану»**. Дата: 24.10.2026. Стратегия: my-pick.

## Проблема

Текущий продукт использует seasonal-estimated-2.1-w84. Старый MoneyVis-кандидат обучался на одном клиенте и рекурсивно предсказывал следующий день; это может накапливать ошибки на 30-дневном горизонте. Старый Berka-классификатор оценивает другую популяцию и даёт много ложных предупреждений. Простая замена продукта этими весами не обоснована.

## Границы работы

Только локальный резерв: исходники, веса, протоколы, тесты и сравнение. Не менять реестр default-модели, основной checkout, API-контракт, сервер или БД. Не делать коммиты и push. Для подключения после проверки подготовить отдельный явный адаптер с прежним ForecastInput/ForecastResult и возможностью возврата к текущей модели.

## Данные

Основное обучение — набор организаторов (SHA256 e753802b7f7a2eecb7b5a558f9923b529e711c40fe431774750904b62ec79987). Проверить даты, направление, копейки, конец дня, пропуски, дубликаты и сверку денежных потоков. Не использовать будущие агрегаты companies.csv. Не смешивать рубли с GBP/CZK.

MoneyVis и Berka — отдельные внешние проверки. Совместное обучение между доменами допускается только как отдельный последующий эксперимент с нормализацией, никогда как молчаливое увеличение выборки. Лицензии банковских источников не считать автоматически разрешением на публикацию. Сырые данные не передавать внешним моделям.

## Кандидаты первого этапа

1. Точная текущая default-модель из `get_forecast_service()`, плюс простой baseline7.
2. Прямой CatBoost-прогноз нормированных накопленных поступлений и списаний для горизонтов 1—30 дней. Признаки только на дату среза: лаги/суммы/разброс за 7/14/28/56/84 дней, частота нулевых дней, день недели, положение в месяце и известные будущие календарные даты, горизонт. Масштаб определяется только из прошлого; ID компании не служит запоминающим признаком. Отдельный бухгалтерский контроль: остаток = opening + поступления − списания.
3. Комбинация текущего и прямого прогноза с весами 0.25/0.5/0.75, выбранными только на validation. Прогноз накопленных потоков ограничивается неотрицательностью и монотонностью; метрики считаются после этого преобразования.

Бюджет первой сетки: CatBoost depths 4/6, iterations до 500, learning_rate 0.04, seed 20261024, не более 4 CPU-потоков; отказ от многократного расширения сетки по результатам test. Ускорение GPU — отдельное воспроизводимое решение, не обязательное условие. Chronos-2 пока в backlog: потенциально полезен, но не доказано превосходство на наших данных.

## Проверка без утечки

- Сохранить прежнее разделение компаний: SHA256(company_id), первый байт mod5 == 0 — отдельная группа переноса. Общая модель не обучается на её целях.
- Fit на development-компаниях с целями не позднее 31.12.2025. Перекрывающиеся обучающие окна допустимы только внутри fit; равный суммарный вес компаний.
- Validation: срезы 31.01, 28.02, 31.03.2026, горизонт 30 дней, цели не позже 30.04.2026. Выбор гиперпараметров и веса комбинации здесь.
- Отдельный период настройки неопределённости: срезы 30.04, 31.05, 30.06.2026 с целями до 30.07.2026. Параметры точки заморожены. Не выбирать порог предупреждения по финальной проверке.
- Ретроспективная проверка: срезы 31.07 и 31.08.2026; development и отдельные компании показываются раздельно. Эти месяцы **уже изучались раньше**, поэтому это не новая независимая оценка обобщения.
- Настоящая окончательная проверка — новый контрольный файл организаторов с заранее зафиксированным cutoff. При отсутствии будущего факта нельзя посчитать честные MAE/F1 будущего; нужен ретроспективный срез внутри файла.
- Никаких случайных splits отдельных строк/дней, интерполяции будущими значениями и использования actual future при рекурсивном/многошаговом прогнозе.
- Непроверенные остатки и неполнота не превращаются в нулевые факты. Число исключённых окон и причины публикуются для всех кандидатов одинаково. Дополнительно показывается покрытие полного набора, чтобы исключение сложных случаев не скрывало ограничения.

## Метрики и выбор

Точка: MAE/MSE/RMSE дневного остатка и накопленных потоков, ошибка конца горизонта, отдельные горизонты 7/14/30, macro по компаниям и общий показатель. Денежные единицы раскрываются. MAPE не основной критерий из-за нулевых и отрицательных остатков.

Риск: отдельно отрицательный день и хотя бы один новый отрицательный остаток за горизонт при opening >= 0. Accuracy/Precision/Recall/F1/F2, TP/FP/TN/FN, PR-AUC/ROC-AUC, Brier, reliability bins и покрытие вероятности; при одном классе AUC=null с причиной. Существующий минус показывается отдельно. Нельзя объявить прогноз погашения обязательств проверенным по одной банковской выписке.

Критерий точки: >=5% улучшения MAE относительно **текущего продукта** на validation, отсутствие ухудшения более 10% на двух срезах из трёх; отчёт по небольшим компаниям и короткой истории. Финальная проверка раскрывается даже при ухудшении. При непрохождении сохраняется текущая модель.

Вероятности не берутся из набора независимых дневных квантилей: нужны согласованные траектории и проверка калибровки. Первый этап может улучшить точку без подтверждённого улучшения вероятности. Для вероятности отдельное сравнение с raw product и постоянной частотой fit; threshold только из calibration. Не выдавать оценку за калиброванную при малом числе событий.

Парные интервалы разницы ошибок — bootstrap целыми компаниями (seed 20261024, 500 повторов), не независимыми днями. Кроме средних метрик — число счетов, окон, положительных событий, задержка и память.

## Тесты и результат

Проверки отсутствия будущих данных, согласованности денег/потоков, короткой истории, нулей/выбросов, воспроизводимости seed, формата ForecastResult и сохранения поведения текущего default. Существующие тесты модели запускаются на этой базе; интеграционные тесты только на отдельной тестовой БД.

Результат: машиночитаемый отчёт, сравнение до/после, SHA данных и кода, локальные веса и инструкция повторения. Если улучшения не подтверждены — честное решение «не переключать». Обещать максимальные метрики на неизвестном контроле нельзя.
