# 03 — чувствительность предупреждений и устойчивость порога

Статус: approved по разрешению владельца самостоятельно вести локальные эксперименты.
Зафиксировано до нового расчёта; математика/веса01и02не изменяются.

## Причина

Оптимизация F2 по2положительным validation выбрала классификатор с низкой чувствительностью.
Продукту раннего предупреждения нужна явная цена пропуска. Проверяем фиксированную
сетку объединения текущего bootstrap-сигнала и reserve4, выбранного по pinball
на раннем validation. Не выбираем depth по поздним результатам.

## Методы и выбор

- Текущий сигнал p0, reserve4 p1, sqrt(p0*p1), min(p0,p1), (p0+p1)/2.
- Сетка порогов .01/.02/.03/.05/.075/.1/.15/.2/.25/.3/.4/.5/.6/.7/.8/.9.
- Порог и метод выбираются только по объединённым ранним cutoffs январь—июнь2026,
  одинаковым доступным наблюдениям, opening>=0. Данные после30.07не используются.
- Hard recall >=0.8 и не ниже текущего p0 при пороге.5; FPR<=.2. Среди прошедших
  максимальный F2, далее меньше FP, выше порог. При отсутствии решения — не выпускать.
- Отдельная проверка устойчивости: для каждого из6месяцев переизбрать метод/порог
  на остальных5и оценить исключённый месяц. Это sensitivity analysis с использованием
  разных исторических месяцев, **не причинная prequential оценка**, так как часть
  обучающих для политики месяцев позже исключённого.
- После фиксации решения один раз вычислить поздние development/other-company
  метрики, paired company-bootstrap разности F2/recall и реальные TP/FP/FN.

## Ограничения

Данные проверки уже изучались в01/02, поэтому итог — ретроспективная разработка,
не слепая оценка. Финальный контроль организаторов отсутствует. Даже улучшение
всех наблюдаемых метрик не позволяет обещать100%чувствительность на новом файле.

Комбинированный score — некалиброванный показатель риска. Для отчёта Brier/AP/AUC
можно посчитать, но не называть score подтверждённой вероятностью. Модель резерва
также предоставляет денежные квантили независимо от политики предупреждения.

Локальное включение только как явно экспериментальный риск рядом с текущим прогнозом;
никакой замены рабочего сайта, коммитов/push/PR. Если качество переноса не подтверждено,
вернуть диагностический результат и сохранить запрет автоматической активации.
