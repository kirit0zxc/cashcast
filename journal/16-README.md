Пакет работает отдельно от сайта. Здесь сохранены код, выбранные веса и отчёты,
но нет выписок, ключей, подключений к БД или изменения production.

Состав:

- Остаток: Chronos-2 и CatBoost, плавные веса из эксперимента12. Benchmark75/25
  выводится рядом, как и отдельно дообученный Chronos100.
- Поступления и списания: текущий сезонный движок2.1. Новые модели потоков пока
  не показали достаточно устойчивого выигрыша на наших проверках.
- Предупреждение: текущая тревога И (нижний квантиль Chronos100 ниже0 ИЛИ
  оценка необходимого резерва CatBoost>=0.3). Это правило14.
- Общей калиброванной вероятности для комбинации нет: поле возвращается `null`.
  Оценка резерва указана отдельно как некалиброванная, чтобы её не путали с гарантией.

## Запуск на этом компьютере

Открыть PowerShell в папке пакета
`C:/Users/kirito/Documents/Codex/2026-10-03/new-chat/outputs/cashcast-local-candidate-v16`.
Используются два существующих изолированных окружения. Новые зависимости в сайт
не устанавливаются. Версии перечислены в `reports/ENVIRONMENTS.json`.

```powershell
$tabularPython='../../work/cashcast-eval-env/Scripts/python.exe'
$chronosPython='../../work/cashcast-chronos-env/Scripts/python.exe'
$snapshotPath='C:/путь/к/forecast-input.json'

& $tabularPython -m evaluation.liquidity_risk.offline_bundle `
  --snapshot $snapshotPath --manifest manifest.json `
  --tabular-python $tabularPython --chronos-python $chronosPython `
  --output result.json
```

Вход — JSONснимок `ForecastInputCodec`, версия1. Пример только из синтетических
тестовых операций: `example-input.json`. Для первого запуска замените `$snapshotPath`
на `example-input.json`. Сырые банковские файлы напрямую этот CLI не импортирует.
Снимок строится существующим импортом/кодеком CashCast; сайт для демонстрационного
примера не нужен. Python читает input, проверяет SHAфайлов из manifest и запускает
локальные процессы моделей. Никаких вызовов внешних LLM или банковских API нет.

## Как читать result.json

- `current`: дневные тройки [поступления, списания, остаток] текущей модели.
- `balance_minor`: исследовательская точка остатка; `benchmark75_25_minor` — сравнение.
- `finetuned_balance_minor`: отдельная точка дообученного Chronos100.
- `independent_flows_minor`: независимо выбранные прогнозы поступлений/списаний.
- `reconciled_scenario`: тройки после математического согласования с остатком.
  Начальный остаток плюс накопленные поступления минус списания здесь точно равен
  прогнозному остатку. Согласование меняет потоки и ухудшало их ошибки в опыте08;
  это отдельный сценарий, а не доказанное улучшение прогноза потоков.
- `risk.new_gap_warning`: булевое предупреждение правила14.
- `risk.status=already_negative`: счёт уже в минусе, задача нового разрыва неприменима.
- `risk.status=unavailable`: недостаточно информации для сравнимой оценки риска.
- `fallback=true`: Chronosне получил пригодную историю, использован текущий выход.

Все деньги — целые копейки; делить на100 для рублей. Дни начинаются после `as_of`.
Для горизонта не30 или явных планов/сценариев/регулярностей DTO кандидат возвращает
`unavailable`, а текущий прогноз сохраняется. Его нельзя выдавать за проверенную
модель сценарного анализа. Дневные квантили не являются вероятностью разрыва за месяц.

## Проверки и перенос

`reports/16-verification.json` — проверки21реального окна через отдельные процессы;
`reports/16-edge-verification.json` — будущие/чужие операции и неподдержанный горизонт.
Оригинальные весовые файлы Chronosне менялись при дообучении; отдельный checkpoint
имеет свой hash. Исходники и веса пакета закреплены в `manifest.json`.

Для другого компьютера нужны Python3.12 и совместимые отдельные окружения из
указанных версий; заменить пути к интерпретаторам. Холодная установка на другом
компьютере отдельно не проверялась. CPUзапуск работает; CUDAне требуется.
Папка переносима вместе с весами, без исходного датасета. Полное переобучение
требует ZIPорганизаторов и исследовательских протоколов/скриптов, описанных в reports.
