# Результат локального резерва CashCast

24.10.2026. Основание: main a92bd5013b5b5d7e5008157815160b67fd762edf.

**Обучен и проверен новый кандидат. Автоматическая замена текущей модели запрещена проверкой выпуска: обнаружение разрывов не улучшилось. Коммитов, push и изменений сервера не делали.**

## Что сделано

Прямой CatBoost-прогноз поступлений и списаний на1—30дней с календарными признаками, прошлыми лагами и нормализацией по масштабу бизнеса. Две модели (depth4/depth6) и комбинации с текущим прогнозом сравнили с точным default `seasonal-estimated-2.1-w84`. По validation выбрана depth6; после этого параметры не менялись.

Обучение:64080 строк горизонтов,2136 окон,101 компания, цели до31.12.2025. Это зависимые окна одной истории, а не64080 независимых компаний. Каждый бизнес имеет одинаковый суммарный вес. Использован организаторский ZIP с проверенным SHA; будущие строки, метаданные companies.csv и отдельные компании не участвовали в fit.

На CPU обучение моделей заняло8.1и13.1секунды. RTX4060 не использовалась. Медиана расчёта одного окна кандидатом около0.022секунды против0.104секунды текущего движка; это локальное измерение, без БД и сетевого API.

## Кассовые разрывы — причина не выпускать

Определение: новый отрицательный остаток в следующие30дней при неотрицательном opening. Уже начавшийся минус оценивается отдельно.

По точечной кривой кандидат пропустил все4положительных окна поздней проверки:3на development и1на отдельных компаниях. Текущая модель нашла соответственно1из3и1из1. Ложных тревог у кандидата меньше, поэтому Accuracy выглядит выше, но это **не улучшение обнаружения разрывов**.

Вероятностный вариант использует200целых траекторий прошлых ошибок. На данных для настройки только1положительное окно из164; на следующей проверке2из73. На check Brier улучшился с0.09768до0.06174, но константа даёт0.02698и остаётся лучше. Минимальные критерии числа событий и качества не пройдены.

На поздних development-окнах вероятностный кандидат нашёл2из3разрывов,32ложные тревоги; на отдельных компаниях0из1,10ложных тревог. Это оценки при пороге, выбранном только на check, а не на поздних ответах. Полные матрицы, Accuracy/Precision/Recall/F1/F2/ROC-AUC/AP/Brier и покрытие интервалов сохранены в `probabilities.json`.

**release.allowed=false, calibrated=false, production_activated=false.** Улучшение прогнозируемых сумм нельзя продавать как улучшение вероятности разрыва.

## Что можно использовать

Локальный `LocalFallbackService` реализует текущий ForecastInput/ForecastResult. По умолчанию он возвращает действующую модель, пока release не разрешён. Эксперимент доступен только при явном `allow_unreleased=True`.

Для планов/сценариев, горизонта>30, даты до30.06.2026, недостаточной истории или отсутствующего полного артефакта возвращается текущий движок. Такое ограничение сохраняет поведение сайта и исключает применение весов/ошибок, которых ещё не было на историческую дату. Реестр приложения, worker, HTTP API и frontend не менялись. Через сайт новый кандидат не включён.

## Данные и исследование источников

- Организаторский набор — единственный источник нового обучения, соответствует целевой задаче ближе остальных.
- Хэши имеющихся MoneyVis и Berka проверены, их старые результаты изучены. Они не выдаются за новое обучение и не смешаны с рублёвым набором.
- [CTU Financial](https://relational.fel.cvut.cz/dataset/Financial) описывает банковский набор и отдельно предупреждает о завышенной оценке при нарушении временных ограничений. Его стандартная задача — кредитный исход, не наша оценка нового минуса.
- [Kenya Financial Diaries](https://www.fsdkenya.org/research-and-publications/datasets/kenya-financial-diaries-2012-2013-all-transactions/) содержит потоки298домохозяйств. Это другой домен; добавление таких строк само по себе не решает нехватку размеченных бизнес-разрывов. Не загружался и не использовался для fit.
- [Chronos-2](https://auto.gluon.ai/stable/tutorials/timeseries/forecasting-chronos.html) поддерживает прогноз без дообучения и fine-tuning; документация прямо указывает, что fine-tuning не всегда улучшает качество. Сохранён как отдельная будущая гипотеза, не как обещание превосходства.
- [CatBoost MultiRMSE](https://catboost.ai/docs/en/concepts/loss-functions-multiregression) использован для совместного обучения двух денежных целей с весами компаний.

Проверены причинность, сохранение денег, повторяемость, префикс горизонта, планы/сценарии и отказ от автоматического включения неподтверждённого кандидата. Парсер приложения отдельно успешно разобрал150выписок/222420операций:144138поступлений и78282списания, без расхождений направления/суммы/остатка. Это не проверка неизвестного формата организаторского контроля.

Результат первого этапа: полезный кандидат для прогноза сумм, но **не готовая замена модели разрывов**. Следующий обоснованный эксперимент — отдельное обучение детектора новых разрывов на более богатой по событиям выборке, с сохранением неизученного внешнего контроля и отдельной калибровкой. Нельзя получать «лучшие метрики» подбором порога по контрольным ответам или выдачей высокой Accuracy на редком классе за готовность.
