# 09 — условное распределение необходимого резерва

Статус: approved по активной цели и постоянному разрешению локальных экспериментов.
Pre-flight: журнал/правила прочитаны, последний опыт 08 завершён; источник my-pick
по приоритету пользователя улучшить разрывы. План фиксируется до нового кода.

## Гипотеза

Редкий бинарный исход «будет ли минус при фактическом остатке» теряет сведения
из большинства счетов. Обучать P(необходимый резерв > заданный порог | прошлая история)
для фиксированных порогов может быть полезнее. Это множество вопросов к одному
будущему пути, а не новые независимые компании и не доказанные контрфактические сценарии.

## Метод

История и фактический начальный остаток в признаках сохраняются. Меняется отдельный
запрашиваемый порог резерва; будущие потоки не симулируются и не сдвигаются. Сетка
порога в единицах прошлых средних валовых потоков: 0/.25/.5/1/2/4/8/16/32/64,
плюс фактический неотрицательный нормированный остаток. Сетка не зависит от будущего
резерва. Цель — строго R>порог, где R=max(0,-min(cumsum(in-out))).

Горизонты 7/14/30; в признаках используется фиксированная прошлая характеристика
ReserveFeatures для горизонта30, затем query_horizon и log1p(query_threshold).
CatBoost Logloss depth4/6, 600 итераций, lr=.04, l2=8, CPU4, seed20261025.
Монотонность: по горизонту +1, по порогу -1. Документация:
https://catboost.ai/docs/en/references/training-parameters/common#monotone_constraints
Веса уравнивают вклад компаний и повторных запросов к одному окну.

Обучающие факты заканчиваются 2025-12-31, тот же hash split компаний и шаг14дней.
Для каждого глубинного кандидата модель выбирается по LogLoss на ЕСТЕСТВЕННЫХ
порогах/остатках development январь—март, на всех трёх горизонтах. Никаких искусственных
примеров в validation/проверках. Порог тревоги и комбинация с текущим риском выбираются
на development январь—июнь по 30-дневным окнам: recall>=текущего, FPR<=текущего,
минимальный FP, затем FN; при равенстве предпочесть текущий. Сетка .01/.02/.05/.1/
.15/.2/.3/.4/.5/.6/.7/.8/.9, варианты score кандидата, AND/OR с текущим p>=.5.
Если не меньше 5 положительных окон не набирается — оставить текущую политику.

Проверка по тем же пяти фазам, что08, включая другие компании. Старые исходные
предсказания08 используются для точного парного сравнения; согласовать строки по
(company,cutoff), никакого поиска лучшей политики по поздним фактам. Хронологические
ограничения целей старых фаз сохраняются. Данные уже изучались: только ретроспектива.

Измерения: LogLoss/Brier/AUC/AP, естественные частоты и постоянный baseline, все
матрицы/F1/F2/recall/precision, поддержка компаний; отдельно7/14/30. Вероятности
считаются оценками, не подтверждённой калибровкой. Остаток75/25 и потоки08 не меняются.
Release false до проверки отсутствия потери recall и роста FP на поздних группах.

## Риски и проверки

Инъекции владельца и поведение клиента зависят от реального баланса: поэтому
исторический баланс не заменяется порогом, результаты не называются причинным эффектом
пополнения счёта. Повторы порогов/горизонтов не увеличивают число независимых исходов.
Веса, тесты монотонности, границы нуля, отсутствие будущего в признаках, раздельный
выбор по ранним данным, совпадение старых текущих предсказаний08, сохранение/перезагрузка
реальных весов обязательны. Никаких коммитов, push и изменений приложения.
