# 13 — настоящее дообучение Chronos на прошлых остатках

approved по активной цели; до реализации. Предыдущие рисковые CatBoost09–11
уменьшают ложные тревоги ценой одного пропуска; простые признаки не решили задачу.
Проверим адаптацию самой временной модели к денежным рядам организаторов.

Используется локальный Chronos-2 revision29ec3766d36d6f73f0696f85560a422f50e8498c.
API fit прочитан в установленном chronos/chronos2/pipeline.py: он копирует исходную
модель, не меняя скачанный checkpoint. Полный fine-tuning CPU4, batch8, context365,
prediction30, min_past56, learning_rate1e-6, optim=adamw_torch,300шагов,
seed/data_seed20261025. Сохранить checkpoints100/200/300; заранее оцениваем100и300,
200 только промежуточное восстановление, не дополнительный кандидат после просмотра.
Без внешних API и новых production-зависимостей; никаких публикаций.

Только development-компании прежнего hash-split, факты<=2025-12-31. Из каждого
счёта взять самый длинный сверенный сегмент минимум86дней; при равенстве самый ранний.
При несверке закончить сегмент на предыдущем подтверждённом EOD и начать новый
с текущего подтверждённого EOD. Не дорисовывать историю через разрыв. Внутри сверенных
интервалов пустые дни восстанавливаются из netflow. Никаких дат/сумм2026 в train.
Нормализация внешнего ряда: вычесть его первый известный остаток и разделить на
фиксированные1000000копеек. Никаких статистик будущего сегмента. Внутренний нормализатор
Chronos использует контекст. По одному ряду на компанию, чтобы длинные/разбитые счета
не становились дополнительными независимыми компаниями.

Сначала только обучение и сохранение весов. Затем сравнить исходный Chronos,
checkpoint100и300 на январе—марте по MAE/RMSE/квантильному pinball7/14/30.
Выбор точечной модели по среднему отношению MAE к исходному Chronos на3горизонтах
при RMSE<=исходной*1.05 на каждом; исходный всегда допустим.
Для риска отдельный выбор p10-предупреждения checkpoint100/300/исходного и текущего
bootstrap>=.5 на январе—июне: recall>=текущего, FPR<=текущего, minFP, затемFN,
при равенстве текущий. Никакой вероятности горизонта из дневных квантилей.
После заморозки — остальные фазы08, отдельно ранние и поздние другие компании.
Фиксированный ансамбль75/25 остаётся отдельным benchmark, его вес не подбирается заново.

Контроль ресурса: начатьCPU, не устанавливать GPU-стек вслепую. Если библиотека
или ресурс не позволяют обучение, сохранить реальную ошибку, не объявлять fine-tune
успешным. При работающем процессе не запускать дубликат по истечении ожидания.
Тесты: реконструкция сегментов, отсутствие будущего/других компаний в train,
границы несверки, hash исходных весов до/после, конечность выхода дообученной модели.
Цель активна; улучшение не гарантировано, все результаты и ухудшения сохраняются.
