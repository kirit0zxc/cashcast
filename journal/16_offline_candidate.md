#16 — воспроизводимый локальный кандидат из одного снимка

Approved по действующему разрешению. Это сборка уже выбранных специалистов без
новой настройки: текущие поступления/списания; точка12 с весами Chronos0.5/1/0.75
на днях7/14/30 и дополняющим CatBoost; предупреждение14. Отдельно выводить текущий
прогноз, benchmark75/25 и дообученный Chronos100. Планы/сценарии/явные регулярности
DTO и горизонт не30 пока не исследованы: кандидата не выдавать, текущий прогноз
можно вернуть. При недостаточной истории — текущий fallback, обозначенный явно.

Два существующих окружения используются изолированными worker-процессами через
JSONstdin/stdout: CatBoostиChronos. Не смешивать site-packages и не устанавливать
новые зависимости в приложение. Чтение файлов/весов только локальное; сетевые API
и БД не используются. В stdoutникаких исходных операций, только итоговые суммы.
Ошибки worker не маскировать под успешный кандидат.

Дневные потоки и прогноз остатка — независимо оценённые выходы. Не притворяться,
что они согласованы; выдать отдельно согласованный сценарий через ранее проверенный
L2метод с явной оговоркой об ухудшении ошибок потоков из08. Не приклеивать к точке
вероятности/интервалы чужой модели. Общая вероятность fusion=null, булевый сигнал
и составляющие отдельно; уже отрицательный opening обозначается separately.

Проверки: реальный CLI на подтверждённых окнах из каждой фазы (включая положительные
и fallback), совпадение с кэшами12/13/14до копейки/численной погрешности, запрет
будущих операций, отказ неизвестной версии/повреждённых весов, базовая корректность
ошибок worker. Manifesthashesвесов и аналитических исходников. Упаковка без сырых
данных/секретов, с инструкцией повторения. Не новая независимая оценка качества.
