# 06 — исправление масштаба вероятности без потери существующих предупреждений

Одобрено автономным разрешением, фиксируется до расчёта.

Текущий риск обладает полезным ранжированием, но частоты bootstrap сильно завышены
относительно наблюдаемой доли новых разрывов. Проверяем только один параметр:
logit(p_new)=logit(p_old)+b, slope=1. Исходные0/1ограничиваем половиной шага200траекторий:
.0025/.9975. b подбирается bisection по равенству средней вероятности сглаженной
частоте (positives+.5)/(n+1) на всех доступных ранних cutoffs январь—июнь2026.
Цели заканчиваются не позже30.07.2026. Ни новой сетки методов, ни подбора по поздним
ответам. Модель текущего прогноза не переобучается.

Порог предупреждения преобразуется той же функцией из прежнего.5: все существующие
срабатывания должны сохраниться. Поэтому это улучшение ошибки вероятности, если
подтвердится, а не улучшение Precision/Recall. Старые и новые AUC/матрицы проверяются
на совпадение. Brier/LogLoss/reliability оцениваются на более поздних периодах и
отдельных компаниях; compare constant fit-prevalence. Интервалы по целым компаниям.

Событий для доказательства калибровки по-прежнему мало; calibrated=false. Поздние
периоды уже изучались, это ретроспектива. Новый контроль отсутствует.

Это **отдельная30дневная оценка**. Не подменять ею поле рабочего ForecastResult,
оставив старые дневные вероятности: они принадлежат другой модели и могут нарушить
согласованность. Для внедрения нужна совместная переработка/проверка траекторий.
Локальный отчёт, сохранённый intercept и инструкция; без коммитов/push/сайта.
