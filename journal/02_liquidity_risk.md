# 02 — отдельная модель риска и необходимого денежного резерва

Статус: approved, пользователь подтвердил этот план и самостоятельные дальнейшие локальные итерации. Стратегия: my-pick, продолжение B2.

## Основание

Аудит journal/risk-target-audit.json: в2136обучающих окнах лишь24новых разрыва у6компаний, но1916окон имеют положительную потребность в начальном резерве. Это позволяет учиться предсказывать денежный провал даже на историях, где компания имела достаточный запас и фактически не уходила в минус.

Цель резерва = max(0, -min накопленного будущего netflow за30дней). Новый отрицательный остаток наступает тогда и только тогда, когда opening меньше этой величины. Модель получает только прошлые признаки. Цель — будущая величина только при обучении, не вход для прогноза. Потребность до фактических поддерживающих переводов не наблюдается; не заявляем её прогнозирование.

## Проверяемые варианты

1. CatBoost MultiQuantile для нормированного необходимого резерва. Квантили .01/.05/.1/.25/.5/.75/.9/.95/.99; depth4/6, iterations500, lr.04, l2=8, seed20261024, CPU4. Признаки: прежние причинные DirectFeatures на горизонте30 + статистика просадок прошлых недель, нижние квантили недельного netflow, минимальный исторический запас. ID компаний/будущие строки запрещены.
2. Отдельный CatBoostClassifier с Logloss, depth4, iterations500, lr.04, l2=8 и весами компаний. Без oversampling и подмены реальных случаев. Это сравнительный вариант;24окна не считаются24независимыми банкротствами.
3. Ориентиры: текущая модель, исторические30дневные блоки потребности в резерве и константа частоты fit. Никакой подмены всех рисков нулём.

Прямой прогноз поступлений/списаний из01не меняется. Модель риска выдаёт отдельные оценку резерва и сигнал, её нельзя молча называть калиброванной вероятностью.

## Разбиение и выбор

Сохранить разделение компаний и даты эксперимента01: fit-цели<=31.12.2025; validation январь/февраль/март2026; апрель/май calibration; июнь check; июль/август retrospective на development и отдельных компаниях. Первое сравнение оставить на тех же окнах. Положительные окна, компании и независимость раскрыть явно. Уже просмотренные поздние периоды остаются ретроспективными.

Между двумя резервными моделями выбирать по среднему pinball loss всех квантилей на validation, с нормировкой только по прошлому. Порог предупреждения выбирать на validation из .01/.02/.05/.1/.2/.3/.5: F2 при FPR<=10%, tie — больший порог. Для классификатора тот же пороговый протокол. Сравнение направлений риска по F2/AP на validation до просмотра поздних новых предсказаний; итоговые метрики всех кандидатов сохранить. Малое число положительных validation раскрывается как ограничение.

Апрель/май — только проверка переносимости вероятностной шкалы, без сложного изотонического обучения на одном положительном случае. Калибровку не объявлять доказанной при недостатке событий. Не расширять сетку по поздним ответам.

## Метрики и выпуск

Accuracy/Precision/Recall/F1/F2, матрица ошибок, ROC-AUC/AP, Brier и reliability bins, FPR, пропуски, время расчёта. Для резерва дополнительно MAE/MSE/RMSE и pinball/coverage. Все денежные единицы и число оценённых окон указаны; неопределённые метрики — null с объяснением.

Кандидат риска не выпускается, если поздние новые компании имеют меньше TP и не улучшенный F2 относительно текущей модели при объявленном пороге. При маленькой опоре нельзя делать вывод о надёжности: цель этого запуска — исследовательский резерв, не гарантия и не автодеплой. Отдельные артефакты, исходная модель остаётся доступна. Контрольный датасет организаторов ещё отсутствует.

## Реализация и проверки

Новые модули evaluation/liquidity_risk, отдельный launcher02; не изменять математику/веса эксперимента01. Тесты: причинность, равенство метки и opening<reserve, строгая граница нулевого остатка, нормировка, монотонность квантилей/риска по opening, разделение компаний, повторяемость, невозможность включения непроверенного риска в продукт. Итог — отчёт и локальные веса с хэшами, без коммитов/push/production.
