# 05 — внешний предобученный ориентир Chronos-2

Статус: approved по автономному разрешению; до запуска.

Берём официальный amazon/chronos-2 (Apache2.0,120M параметров) для локального
zero-shot сравнения. Никакие выписки не отправляются на внешний API: скачиваются
только пакет и веса. Отдельное окружение, CPU, максимум4потока; production-зависимости
не меняются. Источник:https://huggingface.co/amazon/chronos-2.

Одна заранее выбранная постановка: предсказывать ряд дневных EOD-остатков, восстановленный
по согласованным прошлым потокам/остаткам; контекст до365дней после последней несверки.
Вход строго<=as_of; нет future covariates кроме календаря (если не нужен — не добавляем).
cross_learning=false: разные компании/срезы не могут обменяться будущей историей.
Пустые дни при условии полной выписки заполняются по netflow; известный opening
должен точно совпасть с концом восстановленного ряда.

Chronos не дообучается и не подбирается по поздним результатам. Выбор на validation
между чистым Chronos и фиксированной смесью с текущим p50(.25/.5/.75). Принимаем
кандидата только при>=5%MAE-выигрыша и без ухудшения macro-MAE компаний>5%.
Все последующие периоды раскрываются как ретроспективные, не нетронутый контроль.
Фиксируем revision весов, версии пакетов, параметры инференса, время и SHA.

Цель — проверить независимый класс моделей. Сильный результат на публичных бенчмарках
не считается доказательством качества на наших МСП. Предобучающий корпус не полностью
контролируется нами; совпадения с публичными источниками исключить нельзя.

Никакой вероятности «хотя бы один минус» из независимых дневных квантилей. Здесь
проверяется точечный прогноз и покрытие дневных интервалов; риск отдельной задачей.
При проблеме загрузки/совместимости сохранить причину и не объявлять запуск успешным.
