# Бинарный флаг SR04 на демонстрационном стенде

25.10.2026, прямое согласование владельца: старая модель продолжает рассчитывать
проценты/графики; новая возвращает флаг «да/нет». Недоступность не является «нет».

GET /api/v1/forecasts/{id}, после существующей проверки доступа, дополняет risk.ml_flag:
available, flag (bool|null), reason, model_version, horizon_days=30, history_only=true.
Поле optional, при выключенном CC_RISK_ML_URL — null. Score наружу не передаётся,
probability_any_negative и точки не меняются. Сценарии, короткая/несверенная история,
отрицательный текущий остаток и горизонт не30 дают available=false/flag=null.
Детектор использует неизменный сохранённый input_snapshot, не текущие изменённые факты.
Только прошлые84дня; дневные остатки восстанавливаются и сверяются с якорями.
Успешные ответы кешируются в памяти по полному нормализованному входу и URL, max128;
ошибки не кешируются и не ломают основной прогноз. Таймаут3секунды.

Веса sensitive SR04 и порог0.075 закреплены. Это демонстрационное включение по
запросу владельца; research production_eligible=false не превращается в научное
подтверждение качества. Основной test TP7/FP16/FN4; дополнительный recall37.25%.
В сценариях сигнал недоступен. В базовом прогнозе планы не учитываются детектором,
что явно подписано в интерфейсе. Ненаблюдаемые дни истории блокируют сигнал:
отсутствие записи не считается подтверждённым нулевым потоком. Новых таблиц/миграций нет.

Отдельный контейнер доступен только внутри Docker-сети, порт на хост не публикуется.
По согласованию владельца архив model.zip включён в Git для запуска из чистого клона.
SHA-256 архива: 912e288c90a1ee1294a65bb6051780fed18497d4f736fc70153308c20c1df08b.
В нём веса, код, агрегированные метрики и искусственный пример, без исходных выписок.
Хеш архива проверяется при сборке, внутренний manifest — при запуске. Зависимости
закреплены по рабочему стенду в infra/risk-ml/requirements.lock. Данные запросов не логируются.
Откат: предыдущие образы api/web и compose без CC_RISK_ML_URL; БД не меняется.
