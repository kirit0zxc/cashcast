# Прогноз по умолчанию: seasonal-damped-2.2-w84

Согласовано владельцем25.10.2026: закрепить в репозитории настройку работающего стенда.
`get_forecast_service()` возвращает2.2; реестр также сохраняет точные версии2.1/2.0/1.0.
API ставит новые прогнозы и проверки качества в очередь с версией2.2. Worker исполняет
версию из задания, а не подменяет её текущим default. Ключ повторного запроса включает
версию: прежний прогноз2.1 не возвращается вместо нового2.2. Старые сценарии сохраняют
версию своей базы. Миграции и изменение публичных DTO не нужны.

## Математика и ограничения

2.2 использует исходные траектории2.1 и сдвигает их центр. Нерегулярный дрейф имеет
вес0; обнаруженные регулярности — вес0.1 для дней1–7 и0 после первой недели.
Известные плановые платежи и эффекты сценариев сохраняются полностью. Без планов
центральный прогноз после первой недели практически равен текущему остатку.
Дневные inflow/outflow остаются исходным прогнозом2.1 и не обязаны давать разность
сдвинутых медиан остатка. Это явно отражено в assumptions результата.

У базового прогноза риск пересчитывается по сдвинутым траекториям; процент остаётся
некалиброванной модельной оценкой. Для сценария сдвигаются квантили без пересчёта
траекторий, поэтому вероятность минуса возвращается null. После30-го дня применяется
последний коэффициент с предупреждением об отсутствии проверки этого горизонта.
Переключение default не утверждает превосходство2.2 на любых данных и не меняет веса SR04.
Отдельный бинарный ML-флаг SR04 продолжает работать по существующему контракту.

## Проверка и развёртывание

- Обычная сборка backend используется и API, и worker; серверная ручная правка не нужна.
- Новый API-прогноз и отчёт качества имеют model_version=seasonal-damped-2.2-w84.
- Задание2.1, поставленное до смены default, и сценарий его базы остаются на2.1.
- Уже сохранённые результаты не перезаписываются: для2.2 пользователь запускает новый расчёт.
- Тесты проверяют очередь, worker, раздельный cache по версии, сценарии и инкрементальный путь.
