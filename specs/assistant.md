# Ассистент CashCast — v1

Согласован владельцем 24.10.2026: DeepSeek V4.1 Flash 1017 через OpenRouter,
функции кабинета, графики и таблицы в чате. Изменения только после подтверждения.

## Возможности

Чат привязан к выбранным компании и счёту. Он читает страницы операций, точные суммы
по категориям за весь период, планы, историю прогнозов, сохранённый график,
объяснения, финансовый пульс, сравнение сценария и план-факт. Денежные значения API — копейки.
Числа карточек приходят из тех же серверных обработчиков, что и в обычном кабинете.
Текст модели может ошибаться; графики не генерируются моделью и не исполняют её код.

Действия: создать/изменить/отменить план; изменить категорию; рассчитать прогноз или
сценарий; применить сверку или конкретную связь оплаты; принять предварительно
проверенную выписку либо CSV обязательств. Загрузка файла в чате — только preview:
проверки и сохранение исходника происходят в CashCast, файл не передаётся модели.
Первоначальный прогноз, включая автоматическую сверку однозначных оплат, также требует кнопки.
Для сценария реальные планы не меняются: создаётся отдельный frozen-расчёт.
Управление пользователями, ключами, подключениями и произвольные SQL/URL модели недоступны.

## Подтверждение

`propose_*` создаёт неизменяемое предложение: действие, точные аргументы, счёт,
пользователь, fingerprint финансового состояния и срок 15 минут. Предложение не
выполняет финансовый запрос. В карточке показываются сумма, дата и целевые ID.
Пользователь отдельно нажимает «Подтвердить действие» или «Отменить предложение».
Сообщение «да» в чате не подтверждает. У модели нет инструмента подтверждения.

Подтверждение проверяет сессию, CSRF, роль owner, владельца предложения,
компанию/счёт, срок и fingerprint. Общая блокировка счёта защищает проверку и запись.
Изменившиеся операции/остатки/планы/связи требуют нового предложения (409).
Финансовое действие и итог предложения фиксируются одной транзакцией.
Повтор подтверждения возвращает сохранённый результат без повторного изменения.
Отменённое предложение нельзя подтвердить. Viewer может читать чат, но не предлагать
и не подтверждать изменения. Повторно проверяются права и после ответа провайдера.

## HTTP

Все запросы требуют обычной сессии кабинета; все POST также `X-CSRF-Token`.

| Метод и путь | Назначение |
|---|---|
| GET `/api/v1/assistant/status` | Включён ли провайдер и точный ID модели; ключ не выдаётся |
| POST `/api/v1/companies/{company}/assistant/chat` | `request_id`, `account_id`, `as_of`, 1–12 сообщений user/assistant |
| POST `/api/v1/companies/{company}/accounts/{account}/assistant/actions/{action}` | `decision: confirm/cancel` |
| POST `/api/v1/companies/{company}/accounts/{account}/assistant/uploads` | multipart file, import_kind, необязательное mapping/as_of |

Ответ: `{text, cards, error_code}`. Карточки: table, forecast, comparison, pulse,
action, job, import. Job отображает фактический статус worker и готовый график.
Полная схема в OpenAPI. Ошибки границ — общий `{error:{code,message,...}}`.
Ошибки внешнего провайдера возвращаются в чате с `error_code` и уже полученными
карточками. При сетевом повторе того же сообщения UI повторяет request_id и тело;
сервер возвращает сохранённый ответ. Другое тело с тем же UUID — 409.

## Приватность и пределы

Ключ — `CC_OPENROUTER_API_KEY` исключительно на api. Секрет не попадает в frontend,
worker, JSON API, git или прикладные логи. Запросы отправляются только фиксированному
HTTPS endpoint OpenRouter; перенаправления запрещены. Исходные назначения, реквизиты,
сырой файл, snapshot и checkpoint из инструментов удаляются. Имена контрагентов
заменяются псевдонимами, включая упоминания внутри пояснений Pulse. Свободный текст,
который пользователь сам написал в чат, передаётся провайдеру; предупреждение есть в UI.
У провайдера задано `data_collection=deny`; это не отменяет передачу для обработки.

Не более 100 обращений/пользователь/UTC-день по умолчанию, один активный запрос на
пользователя, до четырёх model calls и восьми инструментов на сообщение, 40 секунд
общего сетевого бюджета, до 2500 выходных токенов на вызов. Верхние цены маршрутизации:
$0.50/M входных и $1.50/M выходных токенов. Это не общий денежный лимит аккаунта:
лимит расходов самого ключа задаётся в OpenRouter. Автоматических ретраев провайдера нет.
Вывод инструмента ограничен; усечение явно обозначается. Страница операций — 50 строк,
история — 20, планы — 200. Суммирование по периоду не ограничено первой страницей.
Подтверждение в чате поддерживает до 20 000 записей каждого вида на счёт.

История видимого чата живёт до очистки/переключения счёта/перезагрузки страницы.
В БД остаются ответы с карточками, предложения и результаты для идемпотентности и аудита;
очистка чата не удаляет их. Полные исходные сообщения не сохраняются, только hash запроса.
Автоматическая политика удаления этих записей пока не введена; это ограничение демо.

## Проверка

Без ключа статус выключен, обычный кабинет продолжает работать. Unit/integration
проверки используют детерминированный подставной ответ провайдера и отдельный PostgreSQL.
Playwright проверяет настоящий preview → отмена → подтверждение через UI без платных
вызовов. Живое подключение проверяется отдельно только на синтетических данных.
