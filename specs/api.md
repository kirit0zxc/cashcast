# Контракт API v1 · реализованная ночная версия

Базовый префикс: `/api/v1`. Полная машинная спецификация — [`openapi.json`](openapi.json),
генерируется из Pydantic-схем командой `python -m app.scripts.export_openapi`.
Перечисленные ручки реализованы по согласованным решениям A/B. Новые предложения в
coordination/decisions не являются реализованными API до ACK и проверенного пакета.
Для утреннего интерфейса: [frontend-handoff.md](frontend-handoff.md).

## Общие правила

- **Аутентификация:** серверная сессия, HttpOnly cookie `cc_session`. На изменяющих запросах
  (POST/PATCH/DELETE) — заголовок `X-CSRF-Token`, значение из cookie `cc_csrf` / ответа `/auth/me`.
- **Изоляция:** все данные под `/companies/{company_id}/...` доступны только членам компании.
  Чужая компания — `404` (не `403`): существование не раскрываем.
- **Деньги:** целые копейки, поля `*_minor`. Валюта MVP — RUB.
- **Единый формат ошибки:**
  ```json
  {"error": {"code": "string", "message": "строка", "field_errors": [], "request_id": "hex"}}
  ```
  `code` стабилен (на него завязывается фронт), `message` — русский текст.
- **Нереализованные ручки** отвечают `501 not_implemented` с этим же форматом.

## Асинхронность прогноза

Прогноз считается в worker. Клиент: `POST .../forecasts` → `202` → опрос `GET /jobs/{id}` →
по `succeeded` читает `GET /forecasts/{forecast_run_id}`. WebSocket для MVP не нужен.

## Повторяемость

`forecast_run` уникален по (account, as_of, horizon, data_version, model_version, seed, scenario_hash).
Повторный запрос с теми же данными возвращает тот же прогон, а не считает заново.

## wiring-v1.1 и plan-fact-api-v1

ForecastInput фиксируется при enqueue в JSONB. Worker и сценарий не перечитывают
новые факты; версия модели закреплена. До успешной базы сценарий409, старый прогон
без сохранённого входа требует пересчёта. Explanations читаются из details этой версии.
Категории сохраняются при commit импорта, ручная категория не перезаписывается.
Неизвестная категория при PATCH422; словарь перечислен в OpenAPI.

План-факт возвращает account_id/as_of/items(event,confirmed_amount_minor),
confirmed_matches и альтернативные proposals. GET не пишет. POST требует CSRF,
подтверждает только безопасные auto; остатки операций и событий проверяются под
блокировкой счёта. Повтор и параллельные вызовы не создают повторных аллокаций.
Неоднозначные предложения не суммируются и не считаются оплатой.

Без версионной истории планов исторический POST409 historical_reconcile_read_only.
GET прошлого409 historical_plan_unavailable, если известный план менялся после среза.
Будущий as_of422. Текущий forecast подтверждает безопасные совпадения и сохраняет
вход в одной транзакции; исторический только читает доступные сведения.
Paid/cancelled события и просрочка передаются модели по snapshot-events-v1.

Вложенные сценарии в MVP409 nested_scenario_not_supported: каждый сценарий создаётся
от исходной базы. factor=0 разрешён для полного отключения нерегулярного притока.
Только RUB: событие другой валюты422, старое валютное событие блокирует расчёт вместо
молчаливого пересчёта в рубли. Импорт, ручная категория, планы и сборка snapshot
используют блокировку счёта; snapshot не смешивает несколько версий входа.

## Транзакция и успешный ответ

Все HTTP-зависимости get_db имеют scope=function. Commit завершается до отправки
ответа: после202можно немедленно читать новый job, после login — использовать сессию.
Ошибка commit возвращает500/internal_error без чувствительного текста, а не ранее
отправленный успех. Минимальная версия FastAPI0.121; закреплённая0.161.1 не менялась.
ASGI-регрессия проверяет порядок after_commit→http.response.start: обычный TestClient
сам ждёт cleanup и не обнаруживает этот дефект надёжно.

## Границы входов

account_id в JSON, multipart и фильтре операций валидируется как UUID: неправильный
формат422validation_error до запроса к БД. Сумма плана/сценария — строгий int1…9e15
копеек (совместим с JS safe integer и аналитическим guard); seed — signed32int.
В одном сценарии максимум50изменений, shift_days0…3650; factor0 остаётся допустимым.
Дата среза не раньше0002-01-02, будущее по-прежнему отвергается. Ограничения длины
полей плана соответствуют БД, значения не обрезаются молча. Актуально в OpenAPI.

## csv-obligations-v1

ресурсному лимиту файл не сканируется до конца; это не обещание полного числа строк.
Ни одна строка с ошибкой не подтверждается частично. Фатальная ошибка header даёт0
обработанных строк. Неверный UTF-8:422invalid_encoding, большой файл413file_too_large.

счёт и источник. Пустой налоговый режим остаётсяnull, происхождение сохраняется.

строкиnull). Под accountlock CSV и ручные планы проверяют общий лимит2000событий,

## Согласованность конкурентных запросов

Просмотр plan-fact удерживает shared account lock на время всех чтений источника;
несколько GET могут идти одновременно. Запись/import/правка используют exclusive
lock. GET не создаёт allocations и не смешивает остаток плана до оплаты с уже
подтверждённой связью после оплаты. Схемы ответа и исторические ограничения прежние.

Параллельные одинаковые POST scenarios сериализуют создание по account lock,
как базовый POST forecasts: оба ответа 202 содержат один forecast_run_id и job_id.
Конкурирующие вкладки не должны получать 500 из-за unique constraint. Базовый
снимок и закреплённая версия модели при этом не изменяются.

Идентичность нового сценария учитывает ID выбранной базы, изменения и прежние
ключи входа/модели/seed. Совпадение выходного seed двух баз не переносит сценарий
между ними. Уже сохранённый сценарий со старым хешем переиспользуется только для
своей базы; его хеш, frozen input и результаты не переписываются при повторе.

## Строгий разбор банковской выписки

Сумма/остаток: десятичная запись до2знаков с точкой или запятой, знак либо бухгалтерские
скобки; группы тысяч по3цифры с обычным/NBSP/узкимпробелом, опциональный суффикс₽/руб./RUB.
Предел абсолютной суммы9e15копеек. Экспонента, лишние дробные знаки и посторонний текст
дают ошибкустроки; финансовые значения не округляются и не очищаются от произвольных букв.
Известные входящие in/credit/приход/поступление/+, исходящие out/debit/расход/списание/-
(безучётарегистра). Указанная вmapping колонкаdirection обязательна и не может быть пустой.

Неизвестная кодировка, неверная структура/экранирование CSV, дублиheaders, недостающие
обязательные колонки, превышения длин и чужая валюта возвращают failedpreview200 с
sample_errors. Commit такогоимпорта409import_failed без фактов. C0/C1/DEL в исходных
ID/ИНН отвергаются доstrip. Исходныеошибочные значения вmessage не копируются.

Банковский ID<=200символов сохраняется целиком; для длины>96 fingerprint=ext-h:SHA256,
прежние короткиеext:ID неизменны. Preview сериализуется accountlock: одинаковые
параллельные загрузки возвращают одинimport_id. Имяфайла>255илиNUL422invalid_import,
счёт с валютой кромеRUB422unsupported_currency. HTTP/Pydantic-схемы не меняются.
