## Контракт импорта

company_id → внешний ID компании; operation_id → ID операции внутри компании;
operation_date → дата; amount → Decimal с преобразованием в копейки;
direction → in/out; counterparty_inn → строка с ведущими нулями;
counterparty_name/payment_purpose сохраняются отдельно; balance_eod → дневной остаток.
Справочник companies содержит industry, first/last_operation_date, operations_count.
По README это один наблюдаемый счёт компании, не все её деньги во всех банках.
Переводы собственных средств влияют на остаток счёта, но не равны операционной выручке.

## Ограничения прогноза и оценки

Не путать отсутствие операций, выходной день и неполную выгрузку. Проверять сверку
остатка; неизвестные суммы не восстанавливать придуманными операциями. Разрывы покрытия
помечать; не считать будущую сверку доступной на исторической дате прогноза.

В архиве нет отдельных счетов/договоров/налогового календаря, меток категорий и истинных
дат возникновения обязательств. Налоговый режим не указан. По назначениям строим
правила; нельзя объявлять их проверенными по отсутствующей эталонной разметке.

Не использовать будущие last_operation_date/operations_count из справочника как
признаки исторического прогноза. first_operation_date также доступен только после
первой наблюдаемой операции. Отсутствие операций в конце не доказывает закрытие.

Обучение — на прошлом, выбор метода — на временных validation-окнах, финальный holdout
отдельно. Для истории до конца периода кандидат holdout: сентябрь 2026; короткие и
оборванные истории оценивать отдельно по доступному покрытию, без выдуманного факта.
Если обучается общая модель, во всех компаниях соблюдается дата среза; метрики
обобщения на новых компаниях требуют отдельного split по company_id.

Овердрафт и пополнение владельцем видны как факт, но не раскрывают истинную нехватку
денег до спасительного перевода. Основная проверяемая цель — отрицательный наблюдаемый
остаток счёта; сценарий без поддержки владельца — отдельное явно подписанное допущение.
Не приравнивать 16 компаний к количеству независимых кассовых разрывов.

Дополнительные будущие счета для демо вводятся отдельно и маркируются как сценарные,
а не как настоящие внешние данные организаторов. Реализацию модели и backtest ещё
предстоит выполнить; обучение данным аудитом не запускалось.
