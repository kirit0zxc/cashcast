# Прогноз и оценка качества

## B0: опорная модель

BaselineForecastService остаётся сравнительным ориентиром: сумма притока и оттока
за (as_of−7, as_of], делённая на 7 целых календарных дней. Учитывается только заданный
account_id. Будущие операции и события с available_at > as_of исключены.
События paid/cancelled и нулевой остаток не добавляются. Квантили baseline совпадают;
вероятность недоступна. Это не итоговая оценка риска.

Датасет проверяется командой из корня репозитория:

```sh
python evaluation/audit_dataset.py --zip /path/cashflow_dataset_participants.zip --output evaluation/dataset-audit.json
cd backend
python -m pytest tests/analytics tests/test_baseline.py -q
```

Аудит проверяет checksum, совпадение двух представлений операций, повторные ключи,
пустые значения, остатки внутри дня и сверку соседних наблюдаемых дней. Публикуется
только агрегированный JSON. Наблюдаемая несверка не доказывает конкретную причину
пропуска. По архиву нельзя измерить точность категорий: эталонных меток нет.

## B3: аналитический прогноз

SeasonalForecastService реализует ForecastService; фабрика get_forecast_service().
Обучение на последних 28/56/84 календарных днях (пока default84, выбор окна по validation
будет зафиксирован B4). Все операции фильтруются по account и <=as_of, RUB проверяется.
Пустые дни считаются нулевыми под допущением полноты выгрузки. Остатки сверяются только
в прошлом; статистика начинается после последней наблюдаемой несверки. Нет обучения
на справочных last_operation_date или operations_count. Внешние recurrences пересчитываются
из причинного списка операций: DTO не несёт происхождения внешней оценки.

Компоненты: среднее нерегулярного потока по дням недели, календарные регулярности,
оставшиеся суммы доступных плановых событий, отдельные изменения сценария.
Исторические устойчивые повторения исключаются из нерегулярного потока. Явное событие
заменяет соответствующую регулярность по recurrence_group либо контрагенту/направлению
и дате±3 дня при единственном совпадении. Сопоставление производится по исходной дате
до delay_event. Оплаченные/отменённые события исключены. Просроченное активное событие
переносится на завтра как допущение, не как утверждение о реальном сроке оплаты.
При неоднозначной связи события и регулярности автоматическое исключение невозможно;
пользователю следует указать recurrence_group, иначе возможен завышенный ожидаемый поток.

Риск: 200 парных bootstrap-траекторий календарных недель с тем же weekday начала,
фиксированный seed. Пары притока/оттока сохраняются; годовая сезонность, будущие сдвиги
режима, спасительные пополнения владельца отдельно не моделируются. Условные p10/p50/p90
и частоты отрицательного остатка НЕ калиброванная гарантия. Дневная вероятность отличается
от вероятности хотя бы одного минуса за горизонт. first_negative/max_deficit — по p50.
Без28 дней после несверки, свежего остатка (<=3 дней) и согласованного opening вероятность
не публикуется; план/точечный прогноз доступны. Квантили траекторий не обязаны равняться
накоплению ожидаемых inflow/outflow: среднее и медиана имеют разный смысл.

Четыре сценария: delay_event (неотрицательный сдвиг известного события),
reduce_irregular_inflow (factor0..1, только остаточный приток), add_expense
(сумма>0, дата внутри горизонта), increase_recurring (factor>=1, известная группа или все).
Исходный ForecastInput и факт не меняются. Неверный вид/сумма/цель/NaN отклоняется.
Одинаковый seed даёт парные сопоставимые симуляции базы и сценария.

Wiring-v1.1: details.summary + details.explanations содержат kind,label,amount_minor?,
source_ref?,detail:{}; без исходных назначений и контрагентов. Дополнительно JSON
содержит daily_components, recurrence_ids, history_days и paths. related_event_ids
содержит только плановые события до первого отрицательного p50, не ID регулярностей.
