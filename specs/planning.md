# Регулярности и план-факт

CalendarRecurrenceDetector работает только с booked_on <= as_of. Группировка:
счёт, валюта, направление, ИНН (или нормализованное имя), категория; при отсутствии
категории — назначение. Без идентификатора контрагента повторение не предполагается.
Суммируются операции одного дня, повторные id исключаются. Нужны минимум три даты.
По последним шести датам проверяется недельный/двухнедельный интервал (±2 дня),
месяц/квартал (±3 дня фазы), отклонение суммы от медианы не более 35%.
Истинный конец месяца имеет календарный якорь 31; фиксированные 28/30 сохраняются; февраль не меняет его на фиксированные 28 дней.
Если ожидаемый платёж просрочен более чем на 3 дня, группа считается устаревшей.
Confidence отражает число наблюдений, не является калиброванной вероятностью.
Группа с одним контрагентом и несколькими разными обязательствами может не выявиться;
это сознательное ограничение эвристики, а не подтверждение отсутствия обязательств.


## B2: план-факт

ConservativePlannedEventMatcher доступен через get_planned_event_matcher(). Он чистый:
не меняет события и не записывает matches. По wiring-v1 A передаёт один account,
только известные на as_of данные и remaining после уже подтверждённых matches.
Дополнение allocation-residual-v1 (предложение B, ACK A ожидается): операции должны
передаваться с вычтенными ранее использованными суммами либо исключаться целиком.
В текущем DTO нет as_of, account у события или истории аллокаций: самостоятельно
восстановить эти границы сервис не может. A обязан обеспечивать их на каждом вызове.

Условия кандидата: активный статус planned/partially_paid, положительный остаток,
RUB, направление совпадает, дата в пределах ±7 дней от due_date, операция не раньше
available_at. Противоречащий контрагент исключается. Без идентичности контрагента
кандидат возможен только при точной сумме. Идентичность сравнивается с ИНН или именем
(в snapshot-v1 planned.counterparty_ref содержит имя).

Автоподтверждение только при единственном ребре в обе стороны, известном контрагенте
и amount <= remaining. Частичная оплата допустима; переплата только кандидат.
Неоднозначные предложения — альтернативы, не аддитивные суммы. Их НЕЛЬЗЯ суммировать
и уменьшать remaining без отдельного решения пользователя и проверки доступных сумм.
Подтверждённые предложения в одном вызове не используют операцию или событие дважды.
Повторные id и смешение счетов отвергаются. Идемпотентность записи и защита от повторного
использования уже подтверждённой операции — ответственность API/БД у A.

Для прогноза источники: факт используется только в прошлом; будущий planned.remaining
используется один раз; recurrence заменяется соответствующим явным событием, а не
складывается с ним. Кандидат план-факта сам по себе не создаёт будущий денежный поток.


## Согласование caller-инвариантов

allocation-residual-v1 подтверждён A-004: операция передаётся с неиспользованным остатком,
блокировки/предел аллокации/идемпотентность реализует A. plan-fact-api-v1 подтверждён
B-009: GET read-only, POST/CSRF только auto_confirm; candidates только альтернативы.
Исторический срез учитывает даты txn, available_at и время создания confirmed-связи,
чтобы позднее подтверждение не стало знанием прошлого. ACK не означает сквозной проверки
реализации API. snapshot-events-v1 ACK A-005 включает закрытые будущие и активные
просроченные события для дедупликации/прогноза; pure сервис это поддерживает.
## Источник будущих обязательств: csv-obligations-v1

`app.modules.planning.sources.parse_obligations_csv(content: str, *, as_of: date,
source_name: str) -> ObligationParseResult` — чистый адаптер без HTTP/ORM/записи оплат.
DTO согласован B015/A011. Result содержит items/errors/content_sha256; item — event,
source_ref,currency,provenance,tax_regime; error — row/field/code без содержимого строки.
Caller запрещает commit всего preview при любой ошибке, даже если items непустые.

UTF8 с необязательным BOM, разделитель`;`, обязательные колонки:
`id;counterparty_ref;direction;amount;currency;due_date;available_at;kind;provenance`.
Опциональная `tax_regime`; неизвестные/дублированные колонки — ошибки. Direction in/out,
currency строго RUB, amount положительное десятичное число с точкой и максимум2знаками
после неё; экспонента/NaN/inf/запятая отклоняются. Даты строго YYYY-MM-DD. Будущий
Целые копейки получаются из десятичных цифр независимо от ambient Decimal context.
available_at даёт future_knowledge. Просроченный due_date допустим, дата не сдвигается.
Kind invoice/obligation/tax; provenance обязателен. Tax regime сохраняется из источника,
пустой →None, автоматического вывода или расчёта налогов нет.

Event/source_ref=`source_name:id`, statusplanned, remaining=amount, sourcecsv.
A передаёт namespace accountUUID:source_name и назначает DBUUID. ИНН/ID — строки,
ведущие нули сохраняются. External id не содержит`:`, чтобы namespace:id имел
однозначную границу. Повтор id внутри файла — ошибка, существующий источник с новым
payload A отклоняет409, оплаты не обнуляются. SHA256 считает исходные UTF8 байты.

Ресурсные границы parser-v1 (переданы A для ACK): файл10MiB,10000строк, namespace<=160,
externalid<=128, полныйsource_ref<=200, сумма<=9e15копеек, каждое поле<=1000символов,
counterparty_ref<=256. Управляющие символы запрещены; private data не логируется.
Превышение отражается error code; невалидные строки не становятся обязательствами.
API/preview/atomic commit/конкуренция/историческая доступность остаются у A по решению
coordination/decisions/csv-obligations-v1.md. Эти поля не отменяют historical_plan_unavailable.

Пример `evaluation/examples/obligations-demo.csv` явно DEMO/synthetic, не налоговая
справка и не фактические обязательства какой-либо компании. Parser не исполняет формулы
CSV и не вызывает сети. Список errors не раскрывает значения платежей.
