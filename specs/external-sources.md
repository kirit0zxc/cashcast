# Демо-интеграции банка, 1С и налоговых документов

База: main a92bd5013b5b5d7e5008157815160b67fd762edf. Поручение владельца
24.10.2026: реализовать интеграции со звёздочкой; уточнение — пока моки, если кейс
не задаёт конкретную систему/протокол. Это отдельная дневная ветка. Модули B не меняются.

## Что покрывается

В исходном кейсе на стр. 6 нужны договоры/счета/налоги, на стр. 7 — банковские
графики кредитов, зарплатный проект, неисполненные платёжки и учётные системы,
например 1С. Данные должны попадать в прогноз с источником. Банк, версия 1С,
авторизация и формат выгрузки ФНС в кейсе не заданы.

Реализован демонстрационный обмен. Живой связи с банком/1С/ФНС, OAuth, переводов,
расчёта налогов по ставкам/календарю нет. Даты и суммы шаблона вымышлены.
Официальные XML/PDF/сканы ФНС и справка сальдо ЕНС не поддерживаются.
Пакет закрывает демо интеграционного пути, а не все дополнительные задачи кейса.

## Источники

`app.modules.external_sources.adapters` возвращает нормализованный SourceBatch.
Набор от 24.10.2026 стабилен: повтор в другой момент не создаёт новый внешний ID.

- bank: 2 платежа кредита (тело и проценты в сумме), ожидаемая зарплата,
  1 неисполненное поручение. Это планы, а не проведённые операции ledger.
- onec: счёт клиенту, счёт поставщика, 2 отдельных платежа договора №9
  (предоплата/остаток с отсрочкой). Полная сумма договора повторно не прибавляется.
- tax: наш демо-CSV. Колонки id;tax_name;amount;due_date;available_at;tax_regime;status.
  UTF-8/BOM, разделитель `;`, даты ISO, сумма в рублях с точкой и до 2 знаков.
  `due` → исходящий план kind/category=tax. `paid/cancelled` пропускаются.
  ID уникальны, суммы положительны, NaN/экспонента/неточные деньги запрещены.

Строки paid/cancelled не являются проведённой банковской оплатой и не закрывают
ранее загруженные планы автоматически. Закрытие выполняется существующей сверкой оплат.

Суммы/сроки берутся из документа, не выводятся из сальдо ЕНС. Данные, ещё не известные
на дату среза, запрещены. Повтор не сбрасывает оплаты, правки и отмену. Изменённый
исходный документ с тем же ID отклоняется 409 целиком. В разных демонаборах нет одного
общего документа; дедупликация одного обязательства между разными реальными системами
потребует отдельного реестра идентичности и пока не обещается.

## API и хранение

- GET `/companies/{company_id}/external-sources`: каталог, mode=demo, явное предупреждение.
- POST `/companies/{company_id}/external-sources/{bank|onec}/preview`:
  `{account_id, as_of?}`, по умолчанию сегодня UTC.
- GET `/companies/{company_id}/external-tax-template`: скачать демо-CSV.
- POST `/companies/{company_id}/external-tax-imports`: multipart account_id/file.
- Подтверждение: существующий POST `/obligation-imports/{import_id}/commit`.

Сессия, tenant/account и CSRF проверяются общими зависимостями. Viewer читает
каталог/шаблон, но не создаёт preview/commit. Чужие объекты — 404. Файл до
min(max_upload_bytes,10MiB), до 10000 строк. Ошибка любой строки запрещает весь commit.
Preview показывает первые 20 корректных документов и помечает усечение. Ошибки не
возвращают исходные значения; номера строк относятся к загруженному налоговому CSV.

SourceBatch переводится в существующий строгий CSV-адаптер, хранится в ObligationImport.
Миграция не нужна. source=csv, source_name=external-demo-{bank|onec|tax}-v1;
provenance содержит источник и ДЕМО. source_payload дополнен external_provider,
external_mode, document_kind/document_label/category. Commit переносит категорию;
прежние CSV без неё совместимы. Дополнения к API аддитивны, контракт B/модель не меняются;
это решение текущего поручения, не выдуманный ACK партнёра.

Preview сохраняет черновик, но не создаёт планы/операции. Commit атомарно сохраняет
планы с общими account lock/лимитами/дедупликацией. Кабинет обновляет планы и вызывает
plansChanged(): реальный forecast POST → PostgreSQL jobs → worker → новый результат.
Старый снимок не меняется. Автообновление запускает UI, не фоновая подписка сервера.

## Проверка и защита

Только отдельные тестовая БД/Compose. Pytest fixtures очищают таблицы; БД приложения
не использовать. Профиль: `pytest tests/test_external_sources.py tests/test_obligations.py -q`.
Frontend: lint/typecheck/unit/build и Playwright external-sources.spec.ts с настоящим worker.
Итоговые результаты и ревью фиксируются после выполнения.

«Импорт данных» → «Банк, 1С и налоги» → получить демоданные → проверить → подтвердить.
Повторить для проверки отсутствия дублей. Налоговый CSV скачать/загрузить; оплаченная
строка пропускается. Открыть планы и новый прогноз. При поздней дате демособытия могут
быть просроченными: набор фиксированный, не настоящие обязательства организации.

Ориентиры для будущих live-адаптеров: [OData 1С](https://v8.1c.ru/platforma/rest-interfeys/),
[форматы обмена 1С](https://v8.1c.ru/erp/treasury/),
[выписка T-Bank API](https://developer.tbank.ru/docs/api/get-api-v-1-statement).
Это не обещание совместимости моков с конкретным API. Для реального подключения
нужны выбранный источник/формат, read-only доступ, сопоставление организации/счёта,
идентичность документов и проверка на стенде. Секреты не идут в frontend/Git.
