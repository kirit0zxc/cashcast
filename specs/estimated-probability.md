# Модельная вероятность минуса, версия2.1

Владелец 24.10.2026 прямо разрешил снять блокировку отображения вероятности.
Новые расчёты по умолчанию используют `seasonal-estimated-2.1-w84`. Старые1.0 и2.0
остаются в реестре, их задания, сценарии, снимки и сохранённые результаты не переводятся
на новую политику. Для появления процента в кабинете нажать «Рассчитать» заново.

Денежная математика2.0, медиана, квантили, seed и200 bootstrap-траекторий не изменяются.
Вероятность за день = доля траекторий с остатком<0 в этот день. Вероятность за период =
доля траекторий с хотя бы одним отрицательным будущим остатком, а не максимум/сумма
дневных вероятностей. Это моделирование сезонного потока с учётом планов/сценария,
не CatBoost из исследовательских PR55/57 и не эмпирически откалиброванная вероятность.
Если исходный остаток уже отрицательный, процент относится к будущему минусу, не к
возникновению нового разрыва. День среза в объединение будущих дней не входит.

Глобальный запрет B6 снят только для2.1. Требуются не менее56 пригодных календарных
дней, остаток не старше3 дней и согласованность остатка с операциями. Несверка обрезает
историю по прежнему правилу. При недостаточных данных числовой процент остаётся null,
`risk.available=false`; это не0%. Нулевые пропуски истории — явное предположение модели.

API сохраняет probability_negative и probability_any_negative. RiskOut дополнен
`probability_status=estimated_uncalibrated|unavailable` и `probability_calibrated=false`.
Карточка cash-gaps отдаёт probability с тем же статусом только для нового сохранённого
расчёта2.1. Быстрый cash-gap-preview пересчитывает только медиану и возвращает null:
для вероятности изменённого плана нужен полноценный сценарий через /scenarios.
Сценарии сохраняют версию базы; базовый результат не перезаписывается.

Вероятности работают и при инкрементальном обновлении планов/фактов. Проверка считается
по обновлённым траекториям; результат совпадает с полным расчётом при том же seed/входе.
Контрольные точки разных model_version не переиспользуются между заданиями.

В обзоре, прогнозе, таблице, сравнении сценариев и карточке указывается, что оценка
модельная и не откалибрована. Ассистент получает этот статус через API и инструкцию
не называть его подтверждённым риском. 0%/100% в200 симуляциях не являются гарантией.
Исторические плохие метрики не улучшаются этим изменением и не скрываются.

## Проверка

1. Импортировать согласованную историю минимум56 дней с актуальным остатком.
2. «Рассчитать»: model_version должен быть seasonal-estimated-2.1-w84.
3. Проверить процент в «Обзоре», прогнозе, дневной таблице и карточке разрывов.
4. Создать сценарий с крупным расходом; вероятность пересчитывается, база неизменна.
5. Открыть прежний2.0 расчёт: его null сохранён. Для короткой истории новый процент
   также недоступен. Сохранённый отчёт качества моделей остаётся доступен через /models/quality.
