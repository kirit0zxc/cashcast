# Как проверить кассовый разрыв

1. Запустить Compose по README и войти в кабинет.
2. Выбрать компанию и счёт RUB, импортировать выписку с остатками.
3. Во вкладке «Плановые платежи» добавить будущий расход, превышающий ожидаемый
   остаток на выбранную дату; убедиться, что он входит в горизонт прогноза.
   Для демонстрации используйте отдельный тестовый счёт и явно синтетическую выписку.
4. Дождаться нового успешного расчёта и открыть «Прогноз» → «Кассовые разрывы».
   Карточка показывает дату первого нового минуса, сколько дней до него, максимальную
   нехватку, резерв на начало горизонта, длительность и вклад источников.
5. «Финансирование»: указать получение до разрыва, сумму, дату возврата и стоимость.
   Проверить действие. Возврат внутри горизонта может снова создать дефицит;
   долг после горизонта явно показан. Исходные платежи не изменяются.
6. «Перенос»: выбрать доступный поток, новую дату и подтвердить допустимость
   отсрочки расхода. Налоги, зарплата и другие защищённые расходы не переносятся.

Резерв — минимальная постоянная добавка к начальному остатку по этой медианной кривой.
Он не учитывает собственный возврат; для кредита нужен отдельный preview. При
недостаточной истории отсутствие прогнозного минуса не доказывает безопасность.
Вероятность разрыва остаётся недоступной до подтверждения качества на целевой задаче.

Автоматическая проверка на отдельном Compose project с новой тестовой БД:

```powershell
$env:WEB_PORT='18100'
docker compose -p cashcast-realdata-review -f infra/docker-compose.yml up -d --build
cd frontend
$env:CC_E2E_BASE_URL='http://127.0.0.1:18100'
npx playwright test cash-gaps.spec.ts
```

Node 24, Docker и Chromium должны быть установлены. E2E меняет данные тестового
кабинета: не направлять его на личный или production стенд.

## Проверка реальных данных

Протокол до обучения: `evaluation/REAL-DATA-PLAN.md`. Установка в отдельное окружение:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r evaluation/real-data-requirements.txt
.venv/Scripts/python.exe -m evaluation.real_data.run --moneyvis 'C:/data/moneyvis.csv' --berka data/raw/berka/trans.asc --output evaluation/real-data-results.json --weights data/raw/moneyvis-model
.venv/Scripts/python.exe -m evaluation.real_data.risk --berka data/raw/berka/trans.asc --output evaluation/berka-risk-results.json --weights data/raw/berka/risk.cbm
```

MoneyVis — предоставленный пользователем CSV. Berka trans.asc — из
https://github.com/jlacko/berka-dataset . Скачать отдельно в `data/raw/berka/`.
Не коммитить исходные выписки и веса. Денежные единицы MoneyVis не переименовываются
в рубли и не загружаются в продуктовую БД. Новые модели не меняют реестр/default:
обучение на розничных счетах не является доказательством качества для МСП.
Исходники loader/feature/metrics проверяются обычными backend tests без CatBoost.
