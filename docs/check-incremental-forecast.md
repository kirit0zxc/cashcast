# Проверка частичного обновления прогноза

## Локальный стенд

Откройте http://localhost:18094. Вход: demo@example.com / demo-password.
Это отдельный Docker-стенд с синтетическими данными. Версия — ветка PR #50;
до человеческого слияния в main функция не считается частью main.

## Новые операции

1. Выберите счёт «Проверка новых операций». Импортируйте подготовленную историю
   CashCast-incremental-history.csv через проверку файла и подтверждение.
   Настройка колонок — датасет организаторов (разделитель ;, UTF-8 BOM).
2. Дождитесь автоматического прогноза после импорта; откройте его подробности.
   Запишите ID и начальный остаток. Для пустого счёта первый расчёт полный.
3. Импортируйте CashCast-incremental-new-operations.csv: две новые операции
   сегодняшнего дня — приход 8 000 ₽ и расход 1 500 ₽.
4. После автоматического обновления ожидается «Частичное обновление: новые факты
   учтены…». ID новый, источник — предыдущий расчёт. Начальный остаток вырос
   на 6 500 ₽; обработано 2 новых операции, 168 прежних переиспользовано.
5. Откройте старый прогноз в истории: он остался прежним. Повторный импорт второго
   файла не должен создавать дубли; идентичный прогноз может вернуть прежний ID.

Файлы синтетические и рассчитаны на дату подготовки 24.10.2026 UTC.
Новые данные могут изменить регулярности и весь будущий график: он не обязан
просто сдвинуться на сумму двух операций.

## Проверка в Network

F12 -> Network -> Fetch/XHR -> GET /api/v1/forecasts/<новый-id>.
Проверить status=succeeded, calculation.mode=incremental,
reason=observed_data_changed, source_forecast_id предыдущего совместимого запуска,
categorized_transactions=2 и reused_transactions=168.

При движении окна может заново строиться bootstrap-сетка: число новых траекторий
не обязано быть нулём. Скорость ответа сама по себе ничего не доказывает.
points и opening_balance_minor выражены в копейках: 6 500 ₽ = 650 000.

## Плановые платежи

Рассчитайте базу на сегодняшнюю дату UTC. Добавьте расход 10 000 ₽ через 5 дней
с новым контрагентом «Тест частичного обновления». Автоматический прогноз должен
иметь reason=planned_events_changed, источник предыдущего запуска и 0 новых
траекторий. До платежа значения прежние; после него медиана ниже на 10 000 ₽.
Отмените платёж: новый частичный расчёт возвращает сумму.
Исторический срез не знает план, созданный сегодня.

## Полный расчёт и перезапуск

Первый запуск, старый/повреждённый checkpoint, другой seed/горизонт/модель и сценарии
используют full. Новые факты и движение даты вперёд сами по себе теперь не требуют full.
Изменение горизонта через API на ещё не рассчитанный должно дать full.
Перезапуск только worker своего compose-проекта не удаляет checkpoint: после
следующего нового импорта/плана частичный режим должен сохраниться.

## Автотесты

Backend — исключительно отдельная уничтожаемая PostgreSQL с именем *_test:
fixtures очищают таблицы, не запускайте их на БД кабинета.

```powershell
$env:CC_TEST_DATABASE_URL = 'postgresql+psycopg://USER:PASSWORD@localhost:PORT/cashcast_test'
$env:CC_DATABASE_URL = $env:CC_TEST_DATABASE_URL
.venv/Scripts/python.exe -m pytest tests/analytics/test_incremental_forecast.py tests/analytics/test_incremental_ledger.py tests/test_incremental_forecast.py
```

UI — отдельный тестовый стенд без моков (тест добавляет синтетические данные):

```powershell
$env:CC_E2E_BASE_URL = 'http://127.0.0.1:18094'
npm.cmd run test:e2e -- incremental
```

Тесты сравнивают результат с независимой замороженной полной моделью, проверяют
дельту, восстановление состояния, изоляцию и отсутствие дублей.
